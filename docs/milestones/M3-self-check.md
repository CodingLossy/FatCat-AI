## 三、各 PR 专项与真机缺口

- **PR 1(#35)**:M3-plan、ADR 0016、shared 邮件 schema 与 `ApprovalWarning`;CI 绿、oasdiff 增量。
- **PR 2(#36)**:IMAP 同步、本地缓存、账户 REST、子进程加载依赖。Shy 真机 `/test`+`/sync` 通过(见上)。**已发送**同步结果为 0 封(未核实服务器上是否本就为空)。163 **无 CONDSTORE**,走 UID/FLAGS 全量比对路径已跑通,但两次同步间无 FLAGS/删除变化,该分支的「有变化」场景未在真机验证。
- **PR 3(#37)**:`mail.*` 工具、只从草稿发送、会话级污染、14 条注入评测、Node `engines` ≥24。模拟 SMTP 发送与 APPEND 有测。**真实 SMTP 发送已通过**(Shy,`main` @ `6668847`,2026-11-05):真实子进程 runner → 草稿 → 审批 → 163 SMTP 成功,只给自己发了 1 封;结果 `sent: true`、`rejected: []`、`savedToSent: true`;草稿已删除,收件箱 90→91;审批卡片展示完整收件人、主题与正文,`warnings` 为空。同一次测试发现两项缺陷,见 PR 5。
- **PR 4(#38)**:`mail` ItemProvider、附件入库、Web 邮件页与「问 AI」。自动测试与 Shy 只读下钻通过。附件入库:首次测试时邮箱内可入库附件均为加密 PDF(返回 200 且 `chunks: 0` 并带 `error`);**随后在 `main` @ `6668847` 上用明文 PDF(45704 B)与 txt(202 B)在 Shy 真机补测:两者均 `chunks=1`、无错误,通过与 `kb.search` 相同的 FTS 检索能命中 `mail.attachment` 条目,正文可读;INBOX 未读数前后不变(3→3);日志无 error 级行。** 备注:没有 REST 形式的知识库分块搜索接口,仅有工具 `kb.search`。本地不带 `AIP_WEB_DIR` 时 `/` 返回 404,应写进运行说明。
- **PR 5(`docs/m3-wrapup`)**:本自检、CHANGELOG / README 的 M3 说明与本地运行时 `AIP_WEB_DIR` 的说明,以及两项缺陷的修复:
  - **163「已发送」重复保存**:Shy 上发信后「已发送」0→2,同一 Message-ID 有两个 UID。两份的来源不同:一份是 163 **服务器自动保存**的(不经过 AI-Personal),一份是 AI-Personal 按 `appendToSent: true` **由客户端 APPEND** 的。修复(ADR 0016 第 14 节):账户改为「已发送」副本策略 `sentCopy`,默认 `auto`,对 `imap.163.com` / `imap.gmail.com` 不 APPEND,其他主机(含自定义主机)APPEND;用户显式设置的 `append` / `off`(或 `appendToSent: true` / `false`)在任何主机上都生效,不被主机列表覆盖。旧账户按业主 2026-11-06 的决定迁移:旧的 `true` 记为 `auto`,`false` 记为 `off`,所以只有 163 / Gmail 上原为 `true` 的账户(包括 Shy 的 163 账户)停止 APPEND。回归测试:`packages/mail/src/presets.test.ts`(策略 × 主机)、`packages/storage/src/mail.test.ts`(迁移 0011 与新建 / 修改)、`apps/server/src/mail.test.ts`(API 新建、显式设置与 PATCH)。测试中已经产生的那一份重复不会自动删除。
  - **`savedToSent` 的含义**:只表示 AI-Personal 自己的 APPEND 成功,不表示「已发送」里一定有这封邮件,也不核实服务器自动保存。上面真机结果中的 `savedToSent: true` 就是那次多出来的 APPEND。修复后在 163 上 `auto` 策略的预期结果是 `savedToSent: false`、`sentCopy: "server"`;审查侧的复测确认了「已发送」只多 1 封,复测记录里没有这两个字段的取值。
  - **多文件夹同 Message-ID 时按已发送筛选漏信**:同一 Message-ID 只存一份,列表取它的第一个位置后再按文件夹类型筛选;发给自己的邮件先出现在收件箱,所以「已发送」里看不到它(反过来「今天未读」也可能漏掉先出现在已发送里的邮件)。修复:按收件箱 / 已发送筛选时取邮件在该类文件夹中的位置(`mailCache.list`)。回归测试在 `packages/storage/src/mail.test.ts`,去掉修复时会失败。
  - **真机复测**(审查侧,`513a49f`):审查侧于约 `2026-11-05 19:21 PST`(163 网页按北京时间显示为次日 11-06)在 `513a49f` 上用**新建的 163 账户(默认 `auto` 策略)**通过产品创建草稿、审批发送一次:163「已发送」只新增一份;产品同步后,这封邮件在收件箱与已发送中都能看到。这覆盖了新建 163 账户的默认策略,以及发给自己的邮件在两边筛选中都能看到。**没有验证**:旧账户经迁移 0011 后的行为(例如 Shy 原有的 163 账户)、显式 `append` / `off`、自定义主机上的 APPEND。
