说明:语音往返的内存在 vitest 进程里测,包含测试框架自身,也没有按 ADR 0018 的 60 秒等待;它只用来发现「每次往返都留下一点」的泄漏。测试对每轮 RSS 检查规则 3(≤ 60 MiB),对堆检查规则 4(第 3 轮后比第 2 轮后多 ≤ 5 MiB):测试进程的 RSS 受覆盖率插桩与分配器影响,开覆盖率时两轮之间能差 15 MiB 以上,而 gc 后的堆很稳定。堆的小幅上涨来自会话里不断增加的消息。

## 三、M4 期间的决定(都已按建议执行)

1. 真机测试用的语音与图片服务商:业主同意按 OpenAI 兼容接口做,具体服务商待定(方案问题 1)。
2. 本地语音组件、Three.js 推迟;`listening` / `speaking` 由浏览器经 WebSocket 上报;松开后默认自动发送(方案问题 2–5)。
3. 语音请求不写审计日志,只写本地元数据日志;缺少语音配置档或密钥返回 409(#13)。
4. 朗读按段生成 blob 依次播放;空格键只在输入框外按住说话(#14)。
5. 响应中枚举新增取值在 oasdiff 中降为提示(#12,ADR 0010 第 10 节)。
6. M4 文档的日期按业主所在时区(America/Los_Angeles)写,本 PR 把之前的 2026-11-11 统一改为 2026-11-10。
