## 二、与 ADR 0053 不一致或没做的地方

- **插件的调用者**:插件拿到的是 `sha256(插件 id, 账户 id)` 的前 32 位(`ctx.caller`),不是 `ownerId`;插件推来的知识地图条目仍属于安装的管理员(第 14 节「插件开放给成员」)。
- **并发上限用环境变量改**(`FATCAT_AI_MAX_RUNS_PER_ACCOUNT`、`FATCAT_AI_MAX_RUNS`),没有设置页(第 14 节 PR 5)。
- **用户名区分大小写**(`owner` 与 `OWNER` 可以并存):1.0 就是这样,改成不区分需要先处理已有冲突的迁移,没做。
- **删除账户后**,它的附件文件由每天的清理删掉,不是立即删除。
- **群聊**仍然一律忽略,「一个群服务多个账户」不做(和 ADR 原文一致)。
- **`auth reset-totp`** 以前会重置所有账户;现在有多个账户时必须给出用户名,只重置那一个(本 PR)。

## 三、需要业主做的(真实数据与 Windows)

1. **用真实的 1.x 数据目录升级**(先整个备份):启动后确认迁移 0022–0025 都跑了、`backups/` 里有迁移前的备份;`attachments/<账户编号>/` 里有原来的图片、`attachments/.layout-v2` 存在、旧的平铺文件已删除;旧对话里的图片能正常显示。Windows 上做一遍。
2. **Windows:搬迁中断**:附件很多时第一次启动中途强行结束进程,再启动,确认搬完、没有丢图、没有残留 `.part` 文件。
3. **回退演练**:停服务,用升级前的整个备份恢复,启动 1.x,确认能用。
4. **两个真实账户同时用**:一个账户同时开 3 个对话,第 3 个显示「排队中」,前面结束后自动开始;另一个账户同时能正常对话。
5. **成员的日常使用**:用手机浏览器以成员身份登录(HTTPS),保存自己的密钥、用管理员共享的模型、用管理员开放的插件;确认看不到管理员的会话和设置。
6. **管理员降级**:把一个管理员改成成员,确认他以前用 `env:` 或不带前缀的 `file:` 引用的配置档和邮箱显示「缺失」,服务器日志里有一条只列 id 的提示;在 Windows 上点配置档的「测试」和让助手发信,都提示缺失、不发请求;改回管理员后恢复。
7. **停用账户**:给成员绑一个微信或 QQ 渠道,停用这个成员,确认渠道状态变为停下、发消息不再回复;重新启用后渠道能恢复。
8. **离线命令**(Windows 和 Docker 各一次):`auth reset-totp <用户名>` 只重置那个账户;`auth reset-password <用户名>` 改密码后旧会话失效。
9. 英文文档由模型翻译,待校对。
