## 二、与方案的偏差(已写进各 ADR / PR 描述)

1. 调度逻辑放在 `apps/server/src/scheduler/`,没有新建 `packages/scheduler`(ADR 0033)。
2. 没有 WebSocket 事件,任务页有运行中的记录时每 3 秒轮询。
3. 全局设置(`maxConcurrency` 等)没做,用代码默认值。
4. 白名单与文件变化触发只有 API,没有 Web 界面;新邮件触发不按发件人过滤。
5. 自然语言:只有 Web 入口(没有聊天工具 `tasks.propose`、没有微信里生成草稿);卡片只能确认或丢弃,不能逐字段修改;注入用例在 `apps/server` 里,没有并入 `packages/eval`。
6. `memory.sleep`:按 `entity_key` 前两段聚类,没有用向量;手动运行占用当天名额,没有 1 小时冷却;没有「撤销整个整理批次」按钮;没有召回评测对照。
7. `/hooks/:taskId` 没有按 IP 的限流(建议放反向代理上)。
8. 任务运行的审批提醒只出现在 Web,不出现在微信。

## 三、没有验证的部分 / 需要业主决定

- **需要业主决定**:① #52、#54 的迁移确认与合并;② `POST /tasks` 用访问令牌可直接创建已启用的任务,只有自然语言路径要会话确认(ADR 0036,推荐保持);③ 是否要补上第二节第 6、7 项再发 1.0(推荐:`perf:sleep` 与召回评测补上再默认开放 memory.sleep;现在它默认关闭)。
- **内存**:调度器空闲增量、sleep 运行峰值都没测;CI 的 memory-load 在 main 上才会跑。

## 四、业主真机清单(C 不做)

1. 备份后把真实旧库升级到迁移 0016 / 0017,维护任务照常运行,任务页有运行记录。
2. 重启后任务仍在;错过的任务按策略补跑或跳过;改时区后下次运行时间正确;夏令时当天 cron 正确。
3. Windows 真机:`fs.watch` 文件变化(重命名、大批量复制、网络盘 / OneDrive、撤销目录后监听停止)、休眠 / 唤醒后的错过处理、03:30 / 04:00 系统任务。
4. 真实微信:`channel.push` 的审批消息与内容预览、确认后收到推送、拒绝与 30 分钟过期时什么都收不到、只发给绑定的主人、静默时段推迟。
5. 真实邮箱:新邮件触发一次(只带数量);`mail.send` 审批后发出(收件人由业主指定)。
6. Webhook:反向代理 + HTTPS 后调用(401 / 413 / 202 / 429)、令牌重新生成后旧令牌失效、改成别的触发器后令牌作废。
7. 自然语言:几条常见中文说法(「每天早上 8 点」「明天下午三点提醒我」「来新邮件时」)的解析质量,听不懂时的提示,手机上的确认卡片,推送草稿确认后真的推到自己的微信。
8. `memory.sleep`:临时数据目录里打开开关、手动运行、记忆页看到 consolidated 条目与来源、再次手动运行提示名额用完;真实 cheap 模型下整理文本质量(中文输出、200 字内);2C2G 上空闲 / 任务运行中 / sleep 运行中的内存读数。
9. TOTP 开启时 `confirm` 与任务管理操作的行为。
10. 用真实模型跑一个 `agent_prompt` 定时任务(会话标题、运行记录关联会话、结果在最终回答里)。
