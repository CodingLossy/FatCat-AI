## 二、内存(CI 实测,`main`)

| 测量                                                  | 结果                                                              | 来源                                                  |
| ----------------------------------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------- |
| 容器空闲 RSS(规则 1、2:上限 250 MiB,相对基线 111 MiB) | **111.2 MiB**(+0.2%),通过                                         | CI `docker image`,`main` @ `087bb51`(run 42850356508) |
| 万封同步前空闲                                        | 111.7 MiB                                                         | `memory-load.yml`,`main` @ `33dae62`(run 42844684607) |
| 3 轮万封同步,每轮结束 60 秒后                         | 145.2 / 147.0 / 148.2 MiB;每轮约 118–120 秒(约 84 封 / 秒)        | 同上                                                  |
| 规则 3(负载后 60 秒 − 负载前空闲 ≤ 60 MiB)            | 148.2 − 111.7 = **36.5 MiB**,通过                                 | 同上                                                  |
| 规则 4(第 3 轮 − 第 2 轮 ≤ 5 MiB)                     | 148.2 − 147.0 = **1.2 MiB**,通过                                  | 同上                                                  |
| 修复前对照(旧仓库 #48,本机 Linux)                     | 负载前 108.3 MiB,3 轮后 264.7 / 266.0 / 266.1 MiB(增量约 157 MiB) | ADR 0018 第 4 节                                      |

说明:负载后不会回到负载前的 111 MiB,剩下约 35 MiB 是有上限的缓存(V8 老生代按负载调大后的大小、4 MiB SQLite 页缓存、malloc 空闲块),ADR 0018 第 4 节把「能回落」定义为规则 3、4。之后几轮不再明显上涨。上面的数字来自 GitHub Actions 的 Linux runner,不是 Docker 容器里的同步,也不是 Windows。
