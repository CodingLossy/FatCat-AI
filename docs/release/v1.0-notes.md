# FatCat-AI 1.0 发布说明(草稿)

> **状态:草稿,未发布。** 本文件只是仓库里的文字草稿:没有 `v1.0*` tag,没有 GitHub Release,GHCR 上没有镜像。发布日期、版本号和「推荐的模型组合」都要等业主确认。英文版见 [v1.0-notes.en.md](v1.0-notes.en.md)(待校对)。

## 这是什么

FatCat-AI 是可以自己部署的开源个人 AI 助手框架。核心服务只通过版本化的 `/api/v1` HTTP + WebSocket 接口对外,Web UI、命令行和微信都是它的客户端。许可证 AGPL-3.0-only,另有商业许可;SDK 与协议包为 Apache-2.0。**不含任何遥测。**

## 1.0 有什么

按里程碑整理,详情见 [CHANGELOG.md](../../CHANGELOG.md):

- **对话核心(M1)**:接入任意 OpenAI 兼容端点(含 Ollama、DeepSeek、OpenRouter)与 Anthropic、Gemini 原生接口,流式对话,刷新页面后续看进行中的回复;长期记忆(普通事实直接记住并可撤销,敏感信息需要批准)。
- **工具与文件(M2)**:带审批的工具框架、文件与文档读取、网页获取、时间工具、MCP 接入;外部内容一律当作不可信。
- **邮件(M3)**:IMAP / SMTP 账户,同步与检索,发信一律需要审批。
- **语音与图片(M4)**:语音转写与朗读,图片作为对话输入(模型配置档需勾选「支持图片」)。
- **渠道(M5a)**:微信渠道(iLink),配对码绑定,IM 内审批;用户时区设置;记忆召回不完整时的提示。
- **安全与知识地图(M5b)**:密钥文件整体加密(主密钥)、TOTP 两步验证与恢复码、外连目标清单、知识地图(分类浏览、人物、`/map`)。
- **发布准备(M5c)**:手机尺寸的 Web UI、Docker 一键部署(Caddy 自动 HTTPS、2 GB 内存、DNSPod 示例)、API v1 冻结检查(oasdiff 与路由覆盖测试)、CodeQL。

## 资源占用(云容器实测,2C 机器上的数字要业主复测)

- 空闲:约 111 MiB(Docker 镜像主进程 RSS,3 次采样,与基线一致)。
- 对话峰值:约 146 MiB(30 轮含工具调用与约 40 KiB 长回复的对话)。
- 万封邮件同步与微信渠道增量见 [M5c 自检报告](../milestones/M5c-self-check.md)。
- 预算:空闲 ≤ 250 MiB,对话峰值 < 400 MiB(ADR 0018)。

## 已知限制

- 渠道只有**微信**。企业微信推迟,排期另定;QQ 以后再做。
- **单用户**:一个主人账户(表结构预留了 `ownerId`)。
- 知识地图是列表 / 树形浏览器;粒子球导航在 M10。
- 反向代理后登录失败限速是一个共享计数器(ADR 0031 第 3 节):猜密码会让你自己等一分钟,但不会让猜测更容易;TOTP 按用户名单独限速。
- **验证范围**:自动化测试和 CI 在 Linux 上跑。Windows、真实邮箱、真实微信账号、真实验证器 App、手机浏览器(iOS Safari / Android Chrome)、2C2G 实机和真实域名的 HTTPS 签发,由业主按 [M5c 自检报告](../milestones/M5c-self-check.md)的清单实测;清单里标「未验证」的项,发布前请不要当作已验证。
- 英文文档是机器翻译,待校对。

## 安全说明

- 默认只监听 `127.0.0.1`;对外部署必须经反向代理加 HTTPS([部署指南](../deploy/docker.md))。
- 公网部署前请先:开启 TOTP、加密密钥文件(`secrets migrate`)、把主密钥放在环境变量或 Docker secret 里。
- 对外发送(发信、微信回复以外的外连工具)一律需要审批;「设置 → 外连目标」列出了当前配置下服务器会连接的全部地址。
- 日志只写本地,API Key 不入日志、不回显。

## 升级与迁移

- 数据库迁移在启动时自动运行,运行前自动备份。迁移不可逆:回滚要恢复升级前的备份,不要只换旧镜像。
- 项目由 AI-Personal 改名为 FatCat-AI:首次启动会把 `~/.ai-personal` 迁到 `~/.fatcat-ai`(不覆盖已有目录);旧的 `AIP_*` 环境变量暂时可用并提示改名;Docker 生产部署使用新卷名 `fatcat-ai-data`,指南里有从 `ai-personal-data` 复制的命令。
- 镜像标签策略见 [image-tags.md](image-tags.md)。
