## What it is

FatCat-AI is an open-source personal AI assistant framework you host yourself. The core server is reachable only through the versioned `/api/v1` HTTP + WebSocket API; the Web UI, the command line and WeChat are all clients of it. License: AGPL-3.0-only plus a commercial license; the SDK and protocol packages are Apache-2.0. **No telemetry.**

## What 1.0 has

Grouped by milestone; details in [CHANGELOG.md](../../CHANGELOG.md):

- **Chat core (M1).** Any OpenAI-compatible endpoint (including Ollama, DeepSeek, OpenRouter) and the native Anthropic and Gemini APIs; streaming chat that resumes after a page refresh; long-term memory (ordinary facts saved at once and undoable, sensitive ones need approval).
- **Tools and files (M2).** A tool framework with approvals, file and document reading, web fetch, a time tool, MCP servers; external content is always treated as untrusted.
- **Mail (M3).** IMAP / SMTP accounts, sync and search; every send needs approval.
- **Voice and images (M4).** Speech-to-text and read-aloud; images as chat input (the model profile must have "Supports images" ticked).
- **Channels (M5a).** The WeChat channel (iLink), pairing-code binding, approvals inside IM; a user time zone setting; a notice when memory recall was incomplete.
- **Security and the knowledge map (M5b).** Whole-file secrets encryption with a master key, TOTP two-step verification with recovery codes, an egress target list, the knowledge map (category browser, people, `/map`).
- **Release prep (M5c).** A phone-sized Web UI, one-command Docker deployment (Caddy automatic HTTPS, 2 GB sizing, a DNSPod example), API v1 freeze checks (oasdiff and a route-coverage test), CodeQL.

## Resource use (measured in a cloud container; numbers on a 2C machine are for the owner to re-check)

- Idle: about 111 MiB (main-process RSS of the Docker image, three samples, equal to the baseline).
- Chat peak: about 146 MiB (30 turns with tool calls and ~40 KiB long replies).

- Budget: idle ≤ 250 MiB, chat peak < 400 MiB (ADR 0018).

## Known limitations

- The only channel is **WeChat**. WeCom is postponed with no date set; QQ comes later.
- **Single user**: one owner account (the schema reserves `ownerId`).
- The knowledge map is a list / tree browser; particle-sphere navigation is planned for M10.
- Behind a reverse proxy the login failure limiter is one shared counter (ADR 0031 section 3): guessing makes you wait up to a minute but does not make guessing easier; TOTP is limited per user name.
- **What was verified.** Automated tests and CI run on Linux. Windows, a real mailbox, a real WeChat account, a real authenticator app, phone browsers (iOS Safari / Android Chrome), a 2C2G machine and real-domain HTTPS issuance are for the owner to test using the checklist in the [M5c self-check](../milestones/M5c-self-check.md); do not treat items marked "unverified" there as verified.
- The English documents are machine-translated and pending proofreading.

## Security notes

- The server listens on `127.0.0.1` by default; public deployments must sit behind a reverse proxy with HTTPS ([deployment guide](../deploy/docker.en.md)).
- Before going public: turn on TOTP, encrypt the secrets file (`secrets migrate`), and keep the master key in an environment variable or a Docker secret.
- Anything sent outward (mail, network tools beyond the assistant's own replies) needs approval; Settings → Egress targets lists every address the server may connect to under the current configuration.
- Logs stay local; API keys are never logged or echoed.

## Upgrading and migrations

- Database migrations run on start and a backup is taken first. Migrations are not reversible: to roll back, restore the backup taken before the upgrade, do not just switch back to an old image.
- The project was renamed from AI-Personal to FatCat-AI: the first start moves `~/.ai-personal` to `~/.fatcat-ai` (never overwriting an existing directory); old `AIP_*` environment variables still work with a warning; the Docker production setup uses the new volume `fatcat-ai-data`, and the guide has a copy command from `ai-personal-data`.
- The image tag policy is in [image-tags.md](image-tags.md).
