# ADR 0042 · 多智能体(M8)

- 状态:**第 1 步已实施**(业主 2026-11-18 同意迁移 0019;`feat/agents-core`:第 1、2(收窄规则的单会话部分)、4(`shared`/`none`)、5、6 节与第 8 节的 REST 部分);第 2 步(`feat/agent-delegate`,第 6.2 节)已实施委派、预算与并行;`own` 分区、取消子树的界面、恢复、Web 与 CLI 在后续步骤
- 日期:2026-11-18
- 相关:开发计划 M8 一节、ADR 0010(审批)、ADR 0036/0039(任务工具集 `toolSet`)、ADR 0040(插件工具)、《记忆模块补充设计》、`docs/milestones/M8-plan.md`

## 背景

计划对 M8 的要求是:代理 = 人格 / 系统提示 + 模型配置档 + 工具白名单 + 记忆分区;主代理可以用 `delegate` 工具委派子代理,子任务并行、结果汇总,深度与预算有上限;预置四个角色;后台长任务能看进度、取消、恢复;验收是「调研 X 并写成报告存到 ~/Reports」由主代理拆分成并行子任务完成,且任何子代理不能越过自身工具白名单。

现有的基础:`RunManager`(`packages/agent/src/runner.ts`)管理一次对话运行,工具走统一的审批与预授权管线;任务(M6)已经有 `toolSet`(精确名或 `前缀.`)限制一次任务运行可用的工具(`toolInSet`);事件流持久化在 `events` 表;模型配置档在 `model_profiles`;记忆事实有 `scope`。

## 决定(建议)

### 1. 代理(Agent)是一条配置记录

新表 `agents`(迁移 0019,见第 6 节):`id`、`owner_id`、`name`、`role`(`custom` 或预置角色 id)、`system_prompt`、`model_profile_id`(可空,空表示用默认)、`tool_set_json`(必填,与任务 `toolSet` 同一语法)、`memory_scope`(`shared` 只读共享记忆 / `own` 自己的分区 / `none`)、`max_depth`、`max_steps`、`budget_tokens`、`budget_seconds`、`builtin`、`created_at`、`updated_at`。没有「主代理」这条记录:不选代理时行为与今天完全一致(**不改变现有对话**)。

### 2. 工具白名单只能收窄,不能放宽

- 子代理的有效工具集 = 子代理自己的 `toolSet` ∩ 委派者的有效工具集。`delegate` 本身只在委派者的有效工具集里有 `delegate` 时才可用,且子代理默认**没有** `delegate`(需要显式加,并受 `max_depth` 限制)。
- 判断沿用 `toolInSet`,在**工具注册层**(决定把哪些工具给模型看)和**执行层**(收到调用时再查一次)各查一遍;模型编造出不在集合内的工具名同样被拒并记 `denied` 事件。这是验收里「不能越权」的用例来源。
- **审批不下放也不绕过**:子代理的每个需审批的工具调用仍然走同一条审批管线,审批卡标明是哪个子代理发起的;预授权按现有规则匹配,子代理不能继承委派者「本会话已同意」之外的授权。对外发送类工具(`external`)在子代理里一律需要审批,与任务一致。

### 3. 委派、并行与预算

- `delegate({ agent, task, context? })` 返回子代理的最终文本(外加用量)。主代理在一个步骤里发出多个 `delegate` 调用即并行执行;并行度上限默认 3(设置里可改)。
- 每个子运行是一个独立的 `run`(新增 `runs.parent_run_id`、`runs.agent_id`),使用独立的上下文(只拿到 `task` 与 `context`,不继承委派者的整段对话,减少泄露与 token)。
- 上限:`max_depth`(默认 2)、每个运行的 `max_steps`(沿用 `MAX_TOOL_STEPS` 为默认)、`budget_tokens` 与 `budget_seconds`(整棵委派树共享一份预算,先到先停);超限时子代理以「预算用尽」结束并把已得结果返回,委派者可以继续。
- 子代理的输出视为**不可信内容**(与工具输出同等处理),委派者不会把它当作指令。

### 4. 记忆分区

`shared` 与 `none` 之外的 `own` 暂不可选。`none` 的代理不召回记忆、看不到 `memory.` 工具,**也不触发自动抽取**(一轮结束后不调用 `onTurnFinished`)。

`own` 分区用 `memory_facts.scope = 'agent:<id>'`(现有 `scope` 列,无需改表);子代理默认 `shared` 只读,不能写入共享记忆,保存记忆仍走审批。清空代理的分区只删 `agent:<id>` 的事实。

### 5. 预置角色(`builtin = 1`,可复制再改,不可删)

| 角色     | 工具集(初始)        | 备注                    |
| -------- | ------------------- | ----------------------- |
| 研究员   | `web.`、`kb.`       | 只读;不含文件写入与邮件 |
| 邮件秘书 | `mail.`(读取与草稿) | 发送始终需要审批        |
| 文件管家 | `fs.`               | 写入类按现有审批        |
| 日程助手 | `task.`             | 只能操作任务            |

预置角色的系统提示放在代码里,按界面语言提供中英两份;具体工具名以实现时注册表为准。

### 6. 数据库迁移 0019(需要业主确认)

- 新表 `agents`;`runs` 增加可空列 `parent_run_id`、`agent_id`;`events` 不改(用 `payload_json` 里的 `agentId` / `parentRunId` 标注)。
- 现有表与数据不变;迁移前自动备份(与 0018 相同)。回退:旧版本打不开已迁移的库,需要恢复 `backups/db-…-pre-0019.sqlite`。
- **这是需要业主明确同意的一项**:见 `docs/milestones/M8-plan.md` 末尾的问题。

### 6.1 实现注记(第 1 步)

- 预置角色在**首次列出 `/agents` 时创建**(写库);名字与自定义代理重名时加后缀,如「研究员 (2)」。预置角色的提示词不存库(`system_prompt` 为空),按界面语言取自代码。
- 代理被删除后,运行记录里的 `agent_id` 因 `ON DELETE SET NULL` 变成空,所以对这类运行「重试 / 重新生成」会按**没有代理**处理(工具集不再收窄)。要保证不放宽,请先停用而不是删除;若需要区分「从来没有代理」与「代理已删除」,以后要在 `runs` 记一个墓碑标记,需要新的迁移,本步不做。

### 6.2 实现注记(第 2 步:委派)

- `delegate` 是普通的已注册工具(`read`、输出不可信),但**只有运行用的代理的工具集里显式列出 `delegate` 才会出现**。普通对话、定时任务和预置角色都没有它;子代理默认也没有(角色的集合里不含)。其余规则全部沿用:工具集链上每一级都要包含该工具(委派者的集合 ∩ 子代理的集合,创建时不检查、运行时检查),集合外的硬调用按「未知工具」拒绝并审计为 denied。
- 深度:根代理的 `max_depth` 与链上各代理的 `max_depth` 取最小;`max_depth = 0` 表示不能委派。超过时 `delegate` 被收走(模型看不到),硬调用被拒。
- 子运行:每个委派在 `runs` 里新增一行(`parent_run_id` 指向委派者,`agent_id` 为子代理,输入消息沿用委派者的用户消息),没有自己的消息。它在委派者的进程内以独立上下文运行(系统提示 + 子代理人格 + 任务文本),只发出自己的工具调用 / 结果 / 审批事件,不发 `run-started` / `run-finished` / 文本增量,所以现有客户端不会把它当成新的一轮。子运行因服务器重启被中断时和其他未结束的运行一样标为失败。
- 审批:子代理的调用走同一个 `runToolCall`(决策、审批、审计、预授权)。审批卡的说明前缀为 `[代理名]`;定时任务的任务级预授权**不**传给子运行,会话级预授权按原规则生效。委派自己不需要审批,所以审批发生在子代理真正调用工具的时候。
- 并行:同一步里的多个 `delegate` 并发执行,**每个运行内**最多 `delegateParallelism`(默认 3)个同时进行,其余排队;不做整棵树的全局上限,以免父子互相占满名额而死锁(整棵树最多 3^深度 个)。其他工具仍按顺序。
- 预算:`budget_tokens` / `budget_seconds` 沿委派树共享,子代理的消耗同时计入它所有的祖先,先到先停。预算用尽时子代理在当前步骤结束后(时间到则立即中止流式请求)带着已有的最后一段文字返回,`stopped: "budget"`;之后同一棵树里再 `delegate` 会被拒绝,委派者自己可以继续作答。根代理自己的用量也计入它的预算,但不会因此被中止。token 以服务商返回的用量为准,不返回用量的端点按 0 计,所以只有时间预算对它们有效。
- 查询:`activeInSession` / `latestForInput` 只返回根运行(子运行与根运行共用会话和输入消息,不排除就会冒充根运行:幂等重发、冲突提示和取消都会指向子运行)。对子运行 id 调用 `cancel` 会取消它所在的整棵树(转到根运行),`retry` 返回 409 `run_is_delegated`。任务运行的「等待批准」统计整棵委派树的待批审批。
- 按名称找子代理时名称优先于 id(名称与另一个代理的 id 相同时命中名称,影响很小)。
- 输出:返回给委派者的文字最多 20000 字符,超出截断;`delegate` 的输出标记为不可信,所以委派之后本会话的条件预授权失效。
- 记忆:子代理为 `shared` 时不自动注入记忆块(只有它的工具集允许时才能用 `memory.search`),为 `none` 时看不到 `memory.` 工具;委派者为 `none` 时子代理也一样看不到。

### 7. 后台长任务

子运行本来就是持久化的 `run` 加事件流:界面按 `parent_run_id` 画出委派树与每个节点的状态、用量;**取消**一个节点就取消它和它的子树;**恢复**指服务器重启后,把被中断的运行标为 `interrupted`(沿用现有逻辑),由用户点「继续」从最后一个已完成的工具结果重新发起(不重放已执行的有副作用的工具)。

### 8. 对外 API 与客户端

只做向后兼容的增量(`/api/v1`):`/agents` CRUD、`POST /sessions/{id}/messages` 可选 `agentId`、`/runs/{id}/tree`、`POST /runs/{id}/cancel`(已有则扩展到子树)。WebSocket 事件新增可选字段。OpenAPI 与 `packages/client` 同步;Web 增加「代理」页与会话里的委派树视图;CLI 增加 `agents list|show`。

## 不做

- 代理之间的自由对话(只有「委派—返回」一种关系)。
- 跨用户共享代理(1.0 单用户)。
- 子代理使用比委派者更大的工具集或更高的审批豁免。

## 后果

- 新增一张表和两列(迁移 0019)。
- 工具白名单的检查多了一个入口,必须有越权用例:模型调用集合外的工具名、`toolSet` 里写了委派者没有的工具、子代理递归超过 `max_depth`、预算耗尽、取消子树、审批卡归属。
- 并行子运行会增加同时请求模型的数量;并行度上限和预算是防失控的主要手段。
