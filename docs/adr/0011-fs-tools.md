# ADR 0011 · 本地文件工具:授权目录、路径校验与预授权

- 状态:提议(M2 PR 4 `feat/fs-tools`,待业主审阅)
- 日期:2026-11-04
- 来源:开发计划第 7 节(文件权限);`docs/milestones/M2-plan.md` 第 2 节 PR 4;ADR 0010(工具框架与审批)
- 契约代码:`packages/shared/src/fs.ts`;实现:`packages/tools/src/fs/`、`apps/server/src/routes/fs.ts`
- 编号说明:M2 方案中条目索引的 ADR 原拟 0011,顺延为 0012

## 背景

M2 的第一批有副作用的工具是本地文件读写。模型给出的路径完全不可信:可能用 `..`、符号链接、Windows junction、8.3 短文件名、NTFS 备用数据流、设备名或大小写差异绕到授权目录之外。业主要求:预授权用的路径必须先 `realpath` 规范化;Windows 的各种路径特例都要有逃逸测试。

## 决定

### 1. 授权目录

- 授权目录存在 `fs_roots` 表中(迁移 0003),**只能由用户经 API / Web UI 增删**,没有对应的工具,模型无法修改。
- `POST /api/v1/fs/roots { path, label? }`:
  - 服务器对路径做 `fs.realpathSync.native`,必须存在且是目录,保存规范化后的结果(Windows 上即长文件名、真实大小写)。
  - 拒绝文件系统根(`/`、`C:\`)、UNC 与 `\\?\` / `\\.\` 前缀,以及第 2 节中词法检查不通过的路径。
  - 拒绝与已有授权目录重复的路径。
- `DELETE /api/v1/fs/roots/{id}`:同时删除路径前缀落在该目录内的 `fs.*` 预授权,并写审计。PR 6 加入条目索引后,对应的条目一并软删除。
- 每次工具调用都重新读取授权目录并重新 `realpath`,所以撤销立即生效。

### 2. 路径校验(`packages/tools/src/fs/paths.ts`)

先做**词法检查**,不通过就直接拒绝,不访问文件系统:

- 空路径、含 NUL 字符、超过 4096 个字符。
- Windows 上另外检查以下情况。检查函数接受 `platform` 参数,所以在 Linux CI 上也会测试这些规则:
  - `\\?\`、`\\.\` 前缀与 UNC 路径(`\\server\share`)。
  - 备用数据流:盘符之后出现的任何 `:`(`file.txt:secret`、`file.txt::$DATA`)。
  - 设备名:任一段为 `CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`、`CONIN$`、`CONOUT$`,带不带扩展名都算(`nul.txt`)。
  - 以点或空格结尾的段(Windows 会静默去掉,`secret.` 实际指向 `secret`)。

再做**规范化与包含检查**:

1. 相对路径只在恰好有一个授权目录时,相对它解析;否则要求绝对路径。
2. 目标存在时,取 `fs.realpathSync.native`。它会解析符号链接与 junction,并把 8.3 短名展开成长名。
3. 目标不存在时(新建文件),父目录必须存在:取父目录的 `realpath.native`,再拼上已通过词法检查的文件名。
4. 规范化后的路径必须落在某个授权目录的规范化路径之内,并且在分隔符边界上(`D:\Docs` 不包含 `D:\Docs2`)。比较在 Windows 与 macOS 上不区分大小写。
5. 写入与移动前,目标若已存在且是符号链接或 junction(`lstat`),一律拒绝;目标若是目录,也拒绝。

已知的残余风险:检查与实际打开之间存在竞争窗口,有本机写权限的其他进程可以在这期间替换路径。写入时先在**同一个已校验的目录**里创建临时文件,改名前再校验一次父目录,以缩小这个窗口。硬链接无法从路径上识别:单用户、本机部署时,这个风险可以接受。

### 3. 工具

| 工具        | 级别  | 说明                                                                                              |
| ----------- | ----- | ------------------------------------------------------------------------------------------------- |
| `fs.list`   | read  | 列出目录(最多 500 项),不跟随链接;结果标为不可信                                                   |
| `fs.read`   | read  | 读取文本文件,单次最多 256 KB(可用 `offset` 分段读);二进制文件报错(文档解析在 PR 5);结果标为不可信 |
| `fs.search` | read  | 在目录下按文件名与文本内容搜索(最多扫描 2000 个文件、单文件 1 MB、返回 100 条);遍历时不进入链接   |
| `fs.write`  | write | 写入文本文件(≤ 1 MB),先写同目录临时文件再改名;默认不覆盖已有文件;需审批                           |
| `fs.move`   | write | 在授权目录内移动或改名;不能移动授权目录本身;默认不覆盖;需审批                                     |

不提供删除工具,删除以后单独决定。读类工具是 `read` 级别,直接执行;它们只能访问授权目录内的路径。

### 3.1 文档解析(M2 PR 5)

- `fs.read` 遇到 `.pdf`、`.docx`、`.xlsx` 时返回提取出的文本,同样标为不可信:
  - PDF 按页标注 `--- page N ---`,XLSX 按工作表标注 `## 表名`,单元格之间用制表符分隔;
  - 每次最多交给模型 60,000 个字符,`offset` 按字符计;
  - 文件上限 20 MB。
- 解析在 `worker_threads` 中进行:每次解析启动一个 worker,老生代堆上限 256 MB,30 秒超时,完成后立即退出。解析库只在 worker 中加载,主进程的空闲内存不变。
- PDF 用 `unpdf`(MIT,内含 pdf.js,Apache-2.0;解码器为 BSD 许可;没有其他依赖),首次解析时才加载。
- DOCX / XLSX 本身是 ZIP + XML,用自写的最小 ZIP 读取器(只用 `node:zlib`)和 XML 文本提取实现,没有引入 mammoth 或 exceljs:这两者依赖较多,其中 jszip 是 MIT / GPL 双许可。ZIP 读取器只支持 stored 与 deflate,拒绝加密与 ZIP64,并限制单个条目(32 MB)与总的解压大小(64 MB),防止 ZIP 炸弹。
- 只提取文本:不执行宏、脚本或公式,也不访问网络。图片交给多模态模型的功能按业主决定 10 推迟到 M2.x。

### 4. 预授权(落实业主要求)

- `fs.write` 与 `fs.move` 都声明 `requireConstraint: 'pathPrefix'`(ADR 0010 第 3 节):**只能按目录预授权**,不能整体预授权「所有写入」。
- 批准时客户端传来的 `pathPrefix` 先经服务器做与第 2 节相同的词法检查和 `realpath.native` 规范化。路径必须存在、是目录、在授权目录之内,规范化后的结果才写入 `tool_preauth`;否则返回 400。为此,`ToolDefinition` 增加 `normalizeConstraint`,由 core 在保存预授权前调用。
- 匹配时用同样规范化的调用路径,比较规则与第 2 节第 4 条相同。`fs.move` 只有在源路径和目标路径都落在该目录内时才匹配。

### 5. 契约(向后兼容的增量修改)

- 新类型:`FsRoot`、`FsRootInput`。
- 新端点:`GET` / `POST /fs/roots`、`DELETE /fs/roots/{id}`。

## 后果

- 每次调用都会为规范化做几次 `realpath`,开销在毫秒以内。
- CI 增加 Windows 任务,运行 `packages/tools` 的测试,包括 junction、8.3 短名、备用数据流、设备名、大小写与 UNC 的逃逸用例。CI 盘符上没有生成 8.3 短名时,该用例记为跳过,并在日志中说明原因。
