# ADR 0045 · 移动端(M11)

- 状态:提议(M11 方案,待业主审阅;未开始写代码)
- 日期:2026-11-18
- 相关:开发计划 M11 一节、6.1 节(Headless 核心与客户端 API)、第 10 节(零遥测);ADR 0004(API 约定)、ADR 0030(API v1 冻结)、ADR 0036(出站网络清单)、ADR 0044(桌面应用)、`docs/milestones/M11-plan.md`

## 背景

计划把 M11 定为「手机通过 PWA 与桌面本地实例或服务器实例对话、收到任务推送、完成一次审批」,并写了前置条件:「6.1 节的配对、增量同步、断点续传、推送抽象已在阶段一实现并有测试」。**核对现状,这个前置条件不成立**:

| 6.1 节的能力                             | 现状                                                                                                   |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 设备配对(一次性配对码 → 设备令牌,可吊销) | 没有。只有「个人访问令牌」(`/api/v1/tokens`,创建后显示一次、可删除),没有配对码、设备列表、refresh 轮换 |
| 增量同步 `/api/v1/sync`                  | 没有。各列表接口有游标分页,但没有「自某个游标以来的变化」,也没有删除墓碑                               |
| 分片 / 断点续传上传                      | 没有。`/api/v1/attachments` 是一次性 multipart,单张图片 ≤ 5 MiB                                        |
| `NotificationSink` 推送抽象              | 没有。渠道有「出站推送」(给微信发消息),但不是给设备的通知                                              |
| PWA(manifest、service worker、可安装)    | 没有                                                                                                   |
| 语音上传支持 `audio/mp4`                 | 需要核对(iOS Safari 的 MediaRecorder 产出 mp4)                                                         |

所以 M11 第一步不是 PWA,而是把这些前置能力补出来。其中**设备配对与令牌是新的认证入口,推送会新增对浏览器厂商推送服务的出站连接**,都需要业主批准。

## 决定(推荐)

### 1. 设备配对与令牌

- 桌面或 Web 的「添加设备」生成一次性配对码(8 位以上随机、5 分钟有效、只能用一次、限速),界面显示二维码(内容是地址加配对码)。手机打开链接后用配对码换设备令牌,**不需要在手机上输入账户密码**。
- 设备令牌是长期 refresh 令牌(只存哈希)加短期 access 令牌;refresh 每次使用都轮换,旧的立即失效,重放旧 refresh 令牌会吊销整台设备(检测被盗)。`/api/v1/devices` 列出、重命名、吊销;吊销立即生效。
- 设备令牌的权限与个人访问令牌相同(主人身份),但**不能**创建新设备或新令牌、不能改账户、不能关闭 TOTP:这些仍要求完整的登录会话。越权用例必须覆盖。
- 默认只允许在已登录的会话里生成配对码;配对码换令牌的端点只接受回环或已配置的外部地址,并计入审计日志。

这是认证变更,需要业主批准(第 1 个问题)。

**实现细节(第一个 PR,业主已批准本方案)**:

- 配对码 10 位 Crockford Base32(约 50 位熵,显示为 `XXXXX-XXXXX`),5 分钟有效、只能用一次(条件更新保证并发下也只有一次成功)、库里只存 SHA-256;同一账户同时有效的码最多 5 个。设备令牌:access 15 分钟(`aip_dev_` 前缀)、refresh 90 天且每次使用都轮换(`aip_ref_` 前缀),也只存哈希。已用过的 refresh 令牌再次出现,整台设备立即吊销(旧令牌行保留到设备吊销为止,所以任意旧度的重放都能检测到)。
- `/devices/pair` 与 `/devices/token` 是公开端点,按来源地址限速(每分钟 10 次失败);失败统一返回 401,不区分「码不存在 / 已用 / 过期」。创建配对码、改名、吊销、看事件只允许完整的浏览器会话(账户启用 TOTP 时还要通过第二因素);设备令牌与个人访问令牌一律 403。设备令牌另外不能创建或吊销个人访问令牌、不能改两步验证;设备可以 `DELETE /devices/self` 自己登出。
- **审计**:设备事件(创建配对码、配对成功 / 失败、刷新、重放吊销、改名、吊销)写在自己的 `device_events` 表里,不放进 `audit_log`:后者的 `action` 有 CHECK 约束,要扩展就得重建一张有历史数据的表,风险大于收益。事件摘要里不含令牌或配对码。
- 迁移 0020 只新增 `pairing_codes`、`devices`、`device_tokens`、`device_events` 四张表,不改已有表;回滚说明写在迁移文件注释里(用 `pre-0020` 备份恢复)。
- 第 1 个 PR 只做服务端、SDK 和「添加设备」界面。手机端页面(`/pair`、令牌保存与自动刷新、让网页界面改用设备令牌)和「配对码换令牌端点只接受回环或已配置的外部地址」的主机限制,随局域网开关一起放到第 5 个 PR(默认只监听 127.0.0.1,所以现在没有额外暴露)。

### 2. 增量同步

- `GET /api/v1/sync?cursor=...`:返回自游标以来变化的会话、消息、条目(只含手机端缓存的类型),每项带 `updatedAt`;删除用墓碑(`deleted: true`)表示。需要一个迁移:一张只增不改的变更日志表(类型、id、时间、序号),游标就是序号。迁移要业主批准(与 M8 的迁移同样的流程:备份、可回滚说明)。
- 客户端只缓存会话列表与最近消息;离线时可读不可写,写操作在恢复连接后重新发送(沿用现有 `clientMessageId` 幂等)。

### 3. 断点续传上传

- 沿用 `/api/v1/attachments` 的单次上传(≤ 5 MiB 图片已够用),**本里程碑只加语音上传的格式核对**,不新增 tus 式分片协议;大文件上传放到有真实需求时再做。理由:手机端 1.0 的需求是对话、审批、看任务,不是传大文件。

### 4. PWA 外壳

- manifest(图标、`display: standalone`、`start_url`)、service worker **只缓存静态资源与应用壳**,不缓存 API 响应(避免把对话内容留在可被其他站点脚本读到的缓存里;离线读取走第 2 节的显式缓存,放在 IndexedDB 并随登出清空)。
- 安装提示、离线时的「未连接」页面、语音输入(`audio/webm` 与 `audio/mp4` 的录制探测)。

### 5. 推送

- `NotificationSink` 接口放在核心,第一个实现是 Web Push(VAPID):密钥对由服务器首次启动本地生成,**私钥存加密 secrets(ADR 0026)**,不进日志。
- 通知内容只含「有一条待审批 / 任务完成」这类通用文字和一个深链,**不含对话或邮件内容**。
- Web Push 的订阅端点属于浏览器厂商的推送服务(Google / Apple / Mozilla),这是新的出站目标:默认关闭,开启时在设置的外连清单里列出(与第 10 节「设置页列出全部外连目标」一致),并说明推送服务只会看到加密后的通用通知。
- APNs / FCM 与自建推送中继放到原生客户端的时候再说(第 8 节)。

### 6. 无公网 IP 的访问方式

- 文档:Tailscale、ZeroTier、Cloudflare Tunnel、frp 的具体步骤和各自的隐私取舍(谁能看到流量)。**不在本里程碑写自建中继**:端到端加密中继是一个独立的安全设计,放到 1.x,先用文档里的现成方案。

### 7. 桌面 ⇄ 手机

- 桌面版里「添加设备」二维码用的是局域网地址(本机监听仍是回环,所以**桌面版默认不能被手机直接访问**);要让手机连桌面,需要用户在设置里显式打开「允许局域网访问」并看到风险说明。默认关闭,默认回环不变。

### 8. 原生客户端(不在本里程碑实现)

- iOS / Android 原生客户端的技术路线(Tauri v2 mobile 复用 React UI,还是 Swift / Kotlin)留到 PWA 验证后再定,届时写 ADR。PWA 能满足验收,原生客户端不是 M11 的验收项。

### 实现记录:手机端页面(`feat/mobile-web-client`)

- `/pair` 页读出 `?code=` 后立即用 `history.replaceState` 把它从地址栏去掉,并且要点「配对设备」才提交(不自动提交,避免聊天软件的链接预览把一次性配对码用掉)。
- 令牌存在 `localStorage`(键 `fatcat.device`;存不下时只留内存)。access 到期前 60 秒提前刷新;刷新用 Web Locks 串行化,进锁后重新读存储,别的标签页已经换过就直接用新令牌,避免同一个 refresh 被用两次而被服务器当成重放、吊销设备。服务器返回 401/403 才清除本机令牌,网络错误保留。
- SDK `Transport`:`token` 可以是函数,新增 `refreshToken(staleToken)`;请求得到 401 时刷新一次并重试一次,并发的 401 共用同一次刷新。
- WebSocket:浏览器的 WebSocket 不能设请求头,设备 access 令牌放在 `Sec-WebSocket-Protocol: fatcat.v1, fatcat.bearer.<token>`,服务器只回选 `fatcat.v1`(令牌不回显)。长期有效的个人访问令牌**不**接受这种方式(子协议可能出现在代理日志里),仍只走 `Authorization` 头。令牌不放地址栏。
- 设备上的「退出」调用 `DELETE /devices/self`(吊销本设备)并清除本地令牌。
- 吊销立即生效,包括已建立的 WebSocket:用设备令牌建立的连接登记在 `device-sockets.ts`,业主吊销、设备自己登出、refresh 重放吊销三处都会调用 `closeDeviceSockets`,以 4401 `device revoked` 关闭;access 令牌自然过期不断开(重连时用新令牌)。设备令牌握手成功时也会更新「最近使用」。

### 实现记录:增量同步(`feat/sync-api`,迁移 0021 已获业主批准 2026-11-19)

- `change_log(seq AUTOINCREMENT, owner_id, kind, entity_id, session_id, deleted, changed_at, UNIQUE(kind, entity_id))`。**每个实体只有一行**:触发器先删旧行再插入新行,所以表大小不超过实体数,流式回复每个增量都改消息也不会让表膨胀;`seq` 只增不减,游标就是 seq。
- 触发器放在 `sessions`、`messages`、`items` 的 INSERT / UPDATE / DELETE 上,所以所有写入路径(包括外键级联删除会话时的消息)都覆盖,不用改各处仓储。`runs` 的开始 / 结束也会把所属会话记为已变化(会话的 `running` 状态变了)。条目的软删除(`deleted_at`)记为墓碑。注意:SQLite 触发器里 `INSERT OR REPLACE` 会被外层语句的冲突策略覆盖(级联删除时会报 UNIQUE 冲突),所以用「先 DELETE 再 INSERT」。
- 迁移只新增 `change_log` 表和触发器,并按 `updated_at` 回填已有会话、消息、条目;不改任何已有表和数据。`owner_id` 不加外键,避免删账户时触发器再往里写。回滚:停服务,用 `backups/` 里的 `…-pre-0021.sqlite` 恢复再运行旧版本(备份之后写入的数据会丢);也可以只 DROP 触发器和 `change_log`。
- `GET /api/v1/sync?cursor&limit&kinds`:返回变化的实体全文(会话 / 消息 / 条目用现有 DTO)或墓碑,`cursor` 是下次要带的游标,`hasMore` 为真表示还要继续拉。日志指向的实体已经不存在时按墓碑返回。设备令牌可读(只读接口)。
- 初始快照包含全部消息;手机端「只缓存会话列表与最近消息」由客户端用 `kinds=session` 先拉会话、再按需拉消息,服务端不替它裁剪。

### 实现记录:离线只读缓存(`feat/offline-cache`)

- IndexedDB 库 `fatcat-cache`:`sessions`、`messages`(按 `sessionId` 建索引)、`meta`(同步游标)。批次与游标在同一个事务里写入,所以游标和数据始终一致;出错时已写入的批次保留,下次从游标继续。每个会话只留最近 200 条消息(按 `seq`),超出的在写入时删除。
- 只缓存会话和消息(`kinds=session,message`);条目不缓存。写操作不排队:离线时发送、删除仍会失败并显示错误(1.0 的取舍:对话需要联网,不引入离线冲突处理)。
- 只有「连不上服务器」(`FatCatNetworkError`)才回落到缓存;401、404 等服务器的明确回答照常显示。离线启动需要同时有「记住的界面设置」(`localStorage`,只含主题、语言等,不含密钥)和非空的会话缓存,说明这台设备登录过;联网后 `online` 事件会重新确认登录状态。
- 清空缓存的时机:浏览器登出、手机「退出此设备」,以及**服务器明确答复未登录**(`/auth/status` 返回未登录,或同步 / 会话列表返回 401,例如设备被吊销之后手机再联网打开一次)。连不上服务器不会清。清空时先让正在进行的同步停止写入(代数计数 + 取消检查)并等它结束,再清空,否则它的下一批会把数据写回去。一直离线的设备仍保留缓存(不加密),丢失手机的场景除了吊销还依赖手机锁屏;1.0 接受这一点,暂不加设置开关。
- 设备令牌过期的特例:`/auth/status` 是公开端点,过期的设备 access 令牌得到的是 200「未登录」而不是 401,不会触发自动刷新。所以判断登录状态时(`auth-state.ts`),已配对的设备在「未登录」时先用 refresh 令牌换一次再判断;refresh 被服务器拒绝(设备已吊销)才清缓存,refresh 因网络问题失败则按离线处理。这样离线超过 15 分钟的手机恢复联网不会被误清缓存或送回登录页。
