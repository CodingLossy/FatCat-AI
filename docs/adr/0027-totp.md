# ADR 0027 · TOTP 两步验证

- 状态:已采纳(M5b PR 3;实现在 PR 5 `feat/totp`)
- 日期:2026-11-13
- 相关:ADR 0026(主密钥)、ADR 0004(认证)、M5b 方案第 5 节问题 5、开发计划第 7 节
- 依据:RFC 6238(TOTP)与 RFC 4226(HOTP)。净室:只依据这两份 RFC 与本 ADR,不参考任何第三方实现。

## 背景

登录目前是密码加 HttpOnly 会话,并有失败限流。公网暴露之前需要第二因素。开发计划验收项 2:开启 TOTP 后无第二因素无法登录。

## 决定

### 1. 算法

- HMAC-SHA-1、30 秒步长、6 位数字;校验时允许前后各偏 1 个步长(共 3 个步长)。
- 自己用 `node:crypto` 实现(`apps/server/src/auth/totp.ts`),不加依赖。共享密钥 20 字节随机,Base32 编码(32 个字符,无填充)。
- 验证码比较用 `crypto.timingSafeEqual`。
- `otpauth://totp/FatCat-AI:<用户名>?secret=…&issuer=FatCat-AI&algorithm=SHA1&digits=6&period=30`;二维码用 `apps/web/src/QrCode.tsx` 在浏览器里生成,服务器不渲染图片。

### 2. 登录流程

1. `POST /auth/login`(已有)密码通过且账户启用了 TOTP:返回 **202** 与 `LoginChallenge { totpRequired: true, challengeToken, expiresAt }`,**不**设置会话 Cookie。未启用 TOTP 的账户行为与响应不变(200 `LoginResponse`)。
2. `challengeToken` 是 32 字节随机值,服务器只存哈希(内存),**5 分钟**有效,一次性,不能当会话、CSRF 或个人访问令牌使用;重启后失效。
3. `POST /auth/login/totp { challengeToken, code | recoveryCode }`:通过后建立会话并返回 200 `LoginResponse`,会话记录 `second_factor_at`。
4. 密码错误与验证码错误对外返回同一类错误,不区分账户是否存在。

### 3. 重放与恢复码

- 同一时间步长的验证码只能用一次:记录 `last_used_step`,提交的验证码对应步长 ≤ 它则拒绝。
- 启用时生成 **10 个**一次性恢复码,格式 `XXXXX-XXXXX`(Crockford Base32),明文只在启用或重新生成时返回一次;库里只存哈希(SHA-256 加每码独立的随机盐,常数时间比较)。用掉即作废,剩余数量在 `GET /auth/totp` 里返回。
- 重新生成恢复码要密码加第二因素,旧码全部作废。

### 4. 启用与关闭

- `POST /auth/totp/setup { password }`:生成待确认的共享密钥(用 ADR 0026 主密钥加密后入库,标记未启用),返回 `TotpSetup { otpauthUri, secret }`;重复调用覆盖未启用的旧密钥。
- `POST /auth/totp/enable { password, code }`:验证通过后启用,返回 `TotpRecoveryCodes`;**撤销除当前会话外的全部会话**,当前会话记为已通过第二因素。
- `POST /auth/totp/disable { password, code | recoveryCode }`:关闭并删除密钥与恢复码;撤销其他会话。
- 启用和关闭都需要密码加验证码(或关闭时用恢复码)。
- 主密钥不可用(ADR 0026)时,启用与验证都报「密钥不可用」;不回退到不验证。

### 5. 限流

复用 `FailureLimiter`,**按用户名与按 IP 分别**计数(任一超限即锁定),覆盖 `login/totp`、`enable`、`disable`、`recovery-codes`。锁定期间连正确的验证码也拒绝(与密码失败的现有行为一致)。临时凭证的验证失败次数上限 5 次,超过即作废,需重新输入密码。

### 6. 个人访问令牌

- 已有令牌**不受 TOTP 约束**:命令行与 API 客户端继续用令牌,流程不变。
- **创建**令牌(`POST /auth/tokens`)在账户启用 TOTP 时,只允许 `second_factor_at` 非空的会话;个人访问令牌不能创建令牌(已有行为)。启用 TOTP 之前创建的会话在启用时被撤销,所以不会有「没通过第二因素却能建令牌」的旧会话。
- 关闭 TOTP 不撤销令牌。

### 7. 离线重置

验证码与恢复码都丢了:在服务器本机运行 `node dist/index.js auth reset-totp`(需要能读写数据目录,服务器可运行也可停止):删除 TOTP 凭据与恢复码、撤销全部会话、写一条审计日志「TOTP 已本机重置」。不产生任何远程入口。

### 8. 存储草案(迁移 0015,**本 PR 不建表**,编号以合并时为准)

```sql
CREATE TABLE totp_credentials (
  owner_id        TEXT PRIMARY KEY REFERENCES owners(id) ON DELETE CASCADE,
  secret_enc      TEXT NOT NULL,            -- ADR 0026 信封,主密钥加密的共享密钥
  enabled         INTEGER NOT NULL DEFAULT 0 CHECK (enabled IN (0, 1)),
  last_used_step  INTEGER NOT NULL DEFAULT 0, -- 最近一次成功验证码所在的时间步长
  created_at      TEXT NOT NULL,
  enabled_at      TEXT
);

CREATE TABLE totp_recovery_codes (
  id         TEXT PRIMARY KEY,
  owner_id   TEXT NOT NULL REFERENCES owners(id) ON DELETE CASCADE,
  salt       TEXT NOT NULL,
  code_hash  TEXT NOT NULL,
  used_at    TEXT,
  created_at TEXT NOT NULL
);
CREATE INDEX idx_totp_recovery_owner ON totp_recovery_codes(owner_id);

ALTER TABLE auth_sessions ADD COLUMN second_factor_at TEXT;
```

`last_used_step` 更新与恢复码使用都在事务里完成,防止并发重放。

### 9. 接口(shared:`packages/shared/src/auth.ts` 新增)

| 端点                             | 请求 → 响应                                |
| -------------------------------- | ------------------------------------------ |
| `POST /auth/login`(已有)         | 未变;启用 TOTP 时新增 202 `LoginChallenge` |
| `POST /auth/login/totp`          | `TotpLoginRequest` → `LoginResponse`       |
| `GET /auth/totp`                 | → `TotpStatus`                             |
| `POST /auth/totp/setup`          | `TotpSetupRequest` → `TotpSetup`           |
| `POST /auth/totp/enable`         | `TotpEnableRequest` → `TotpRecoveryCodes`  |
| `POST /auth/totp/disable`        | `TotpConfirmRequest` → 204                 |
| `POST /auth/totp/recovery-codes` | `TotpConfirmRequest` → `TotpRecoveryCodes` |

共享密钥、恢复码、二维码内容不入日志、不回显(除上述一次性响应),响应带 `Cache-Control: no-store`。OpenAPI 的路径声明随 PR 5 的路由加入(只增不改;`/auth/login` 只增加 202 响应)。

## 后果

- 开启后没有第二因素无法登录;令牌用户不受影响。
- 丢失主密钥会同时让 TOTP 无法验证,此时只能走离线重置(文档写明)。
- 新迁移 0015 需要业主明确同意。

## 实现 PR 的测试清单(PR 5)

- RFC 6238 附录 B 的 SHA-1 官方测试向量(8 位向量截取为 6 位对照);±1 步长通过、±2 步长失败。
- 重放:同一步长第二次提交失败;并发提交只有一个成功。
- 恢复码一次性;重新生成后旧码失效;哈希不可逆(库里没有明文)。
- 限流:按用户名与按 IP 各自锁定;锁定时正确验证码也拒绝。
- **越权**:临时凭证不能当会话访问任何受保护接口、不能当 CSRF、不能创建令牌;过期(5 分钟)与已使用的临时凭证被拒绝;未通过第二因素的会话不能创建令牌;关闭、重新生成恢复码、启用都要密码加第二因素;个人访问令牌不能操作 `/auth/totp/*`。
- 未启用 TOTP 的账户登录流程与响应不变(回归);启用后其他会话被撤销。
- 主密钥不可用时验证失败而不是放行。
- 扫库测试:共享密钥与恢复码在库里不是明文(与 PR 4 同一测试)。
- 本机重置命令:删除凭据、撤销会话。
- 需业主侧实测:真实手机验证器 App 扫码与登录、时钟偏差 ±30 秒、Windows 浏览器登录。
