# ADR 0015 · 本地知识库

- 状态:提议(M2 PR 9;第 6、7 节在 M2 PR 15 中新增)
- 日期:2026-11-04
- 相关:ADR 0011(文件工具与路径校验)、ADR 0012(条目 API 与 files 提供者)、ADR 0014(嵌入与向量表)、M2 方案 PR 9 与第 7 节

## 背景

M2 方案 PR 9:对授权目录分块(按段落与标题,块大小可配置),嵌入后用 sqlite-vec 检索,没有向量时用 FTS 兜底;工具 `kb.search`(read)返回带来源(文件、页码)的片段;Web 中的引用显示文件名与页码(可点击跳转推迟)。验收:回放评测「这份 PDF 里关于 X 的说法」能引用到正确的文件与页码;删除文件后对应的块与向量被清理。

## 决定

### 1. 哪些文件进入知识库

- 只看 `files` 提供者登记的文件条目(授权目录内,ADR 0012),扩展名为 `.md`、`.markdown`、`.txt`、`.pdf`、`.docx`、`.xlsx`。
- 读取复用 `readAuthorizedFile`:先按 ADR 0011 重新校验路径,文档在 worker 中解析,文本文件最多读 256 KB。失败时记录错误摘要,该文件没有分块。
- **增量**:`kb_sources` 记录每个文件的 `mtime`、`size` 与当时的块大小,三者都没变就跳过。

### 2. 分块

- 先按行切成段落:空行分段;Markdown 标题(`#`–`######`)与 XLSX 工作表名(解析器写成 `## 表名`)作为后续段落的标题;PDF 识别解析器写入的 `--- page N ---` 分页行(只对 `.pdf` 识别,普通文本里同样的行不算页码)。
- 同一页、同一标题下的段落合并到块大小;跨页或换标题时另起一块,保证引用的页码准确。超过块大小的段落按句末标点切开,单句仍过长时按字符切开。
- 块大小在设置 `knowledgeBase.chunkChars` 中,默认 1,000 字符,范围 200–4,000;修改后,各文件在下一次索引时重新分块。
- 每个文件最多 2,000 块。

### 3. 存储(迁移 0006)

- `kb_sources`:每个已索引的文件一行(`item_id` → `items` 级联删除)。
- `kb_chunks`:`(item_id, chunk)` 唯一,带 `page`、`heading`、`text`,以 `item_id` 级联删除。
- `kb_chunks_fts`:FTS5 外部内容表(trigram,与 `items_fts` 一致),由触发器维护。
- 向量用 ADR 0014 的 `embeddings` / `embedding_vec`,以 `(item_id, chunk)` 对应。嵌入文本是「文件名 › 标题」加正文,让短片段也有上下文。

### 4. 索引时机与清理

- 不设常驻任务。每次条目同步结束后(`ItemService` 的 `onSynced`),知识库在后台索引该 owner;同一 owner 同时只运行一次,运行中再次触发时结束后再跑一轮。
- 条目同步的时机沿用 ADR 0012 第 4 节;`kb.search` 执行前也会调用 `syncIfStale`(超过 60 秒才同步),所以新文件最迟在下一次检索之后进入知识库。
- **删除**:文件被删除或授权被撤销后,`files` 提供者把条目软删除。索引时,已软删除但还有分块的条目会删除 `kb_chunks`、`kb_sources`,以及它在 `embeddings` 与 `embed_queue` 中的行(向量行由 ADR 0014 的触发器清理)。文件变短、块数减少时,多出的向量同样删除。
- 检索一律排除软删除的条目,所以在下一次索引之前,已删除的文件也不会出现在结果里。

### 5. 检索与 `kb.search`

- `kb.search`(read,`untrustedOutput`):`{ query: 1–500 字符, limit: 1–10,默认 5 }`。
- 先用向量检索(取 `3 × limit` 个候选,只保留知识库的分块,因为向量表以后也会有记忆等其他条目)。向量不可用(没有 embed 配置档、需要重建、上游失败)或没有结果时,用 FTS 检索(bm25);少于 3 个字符的查询回退为 LIKE。
- 输出是 `KbSearchOutput`:在 `UntrustedContent` 之外加 `mode`(`vector` / `fts`)与 `citations`(编号、条目 id、文件名、真实路径、页码、标题)。正文为 `[n] 文件名, p.页码, 标题` 加片段,总长度上限 12,000 字符。工具说明要求模型按 `[n]` 引用文件名与页码。
- Web 的工具卡片对 `kb.search` 显示引用列表(文件名 · 第 N 页 · 标题,悬停显示路径);点击跳转推迟。

### 6. 按目录选择是否进入知识库(M2 PR 15)

- `fs_roots` 增加 `kb_enabled`(迁移 0008,只用 `ADD COLUMN`),**默认不进入**:授权目录只给文件工具与知识地图用,用户在设置 → 授权目录中勾选「加入知识库」后才会被索引。`FsRoot` 增加 `knowledgeBase`,`FsRootInput` 可选 `knowledgeBase`,新增 `PATCH /fs/roots/{id} { knowledgeBase }`(`packages/shared` 增量契约)。
- 索引时只处理落在已勾选目录里的文件(`isWithin`);取消勾选后,下一次索引删除这些文件的分块、`kb_sources`、嵌入与向量。切换后立即触发条目同步,同步结束后知识库重新索引。
- 升级的已有部署:迁移后所有目录都是未勾选,原有的分块会在下一次索引时清理,需要用户重新勾选。

### 7. 入库前的凭据检测

- 复用记忆的凭据规则(`@fatcat-ai/memory/secrets`,ADR 0007 第 5.5 节):每个分块(正文与标题)先用 `redactCredentials` 把能定位的凭据替换为「[已隐藏凭据]」,替换后仍能检测到凭据的块整块丢弃。原文不进入 `kb_chunks`、FTS 与向量。
- 只处理凭据;手机号、住址等个人信息不脱敏(知识库是用户自己的文件,脱敏会让检索失效)。

## 后果

- 没有新依赖。分块原文存进数据库,大约是被索引文本大小的 1–2 倍(加上 FTS 索引)。
- 没有 embed 配置档时,知识库只靠全文检索,中文的短词(少于 3 个字)走 LIKE。
- 推迟:引用点击跳转、文件监听(现在依赖条目同步)、`.doc` / `.pptx` 等更多格式、超过 256 KB 的纯文本全文。
