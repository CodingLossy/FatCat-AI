# ADR 0041 · 内存只测量、不设门禁(取代 ADR 0018)

- 状态:已实施(业主 2026-11-17 决定)
- 日期:2026-11-17
- 相关:ADR 0018(被本 ADR 取代)、ADR 0040 第 8 节(插件内存)、开发计划第 11、12 节
- 取代:ADR 0018 的规则 1–5(CI 失败条件)和「2 GB 服务器常驻」的承诺

## 背景

ADR 0018 把服务端内存当作一项承诺:2 GB 的小服务器能常驻,空闲 ≤ 250 MiB,CI 超过就失败。业主 2026-11-17 改变了产品定位:FatCat-AI 的主形态是像 QQ、微信那样安装在个人电脑上的桌面 app(M10 起),不再以「2 GB 云服务器上常驻」为目标。桌面 app 的内存按实际需要使用,用户体验靠真实的使用反馈和测量来把关,而不是一个固定数字;同时插件(ADR 0040)和以后的功能需要放开手脚,不应每个 PR 都去争几 MiB。

## 决定

1. **不再承诺**「2 GB 内存的服务器即可常驻运行」,也不再有「空闲 ≤ 250 MiB」「对话峰值 < 400 MiB」「涨幅 > 20% 失败」这些数字承诺。
2. **内存只测量、不设门禁**。CI 和压测脚本继续测量并输出报告,但**任何内存读数都不会让检查失败**;只在读数超出旧阈值时输出 `::notice::` 提示,供审查者参考。
3. 报告保留,并且每个 PR 都能看到:
   - `ci.yml` 的 docker 任务(每个 PR 都跑)用 `scripts/perf/idle-budget.mjs` 测空闲内存,把结果写进 job summary;
   - `memory-load.yml`(push 到 main 与手动触发)继续跑 1 万封邮件同步和微信渠道负载,写 job summary;
   - 涉及插件运行时的 PR 按 ADR 0040 第 8 节在描述里写测量值。
4. 必过检查(lint / typecheck / test / build / docker image 等)的名字和范围不变,只改内存那一步的失败条件。脚本用法错误(退出码 2)和功能性失败(例如对话没有全部完成、同步没有跑完)仍然是失败:那是正确性问题,不是内存预算。
5. `.github/memory-baseline.json` **保留,含义改为「记录值」**:`idleRssMiB` 是最近一次发布测量的空闲内存,报告拿它做对比参考;`channelIncrementMiB.wechat` 是最近记录的上限参考值,不再是上限。改动它不需要理由,也不会让 CI 失败。保留是为了让报告里仍有「相对上一次」的对照,发布时顺手更新即可。
6. 回落与不持续上涨(ADR 0018 第 4 节)的**测法保留**:它们抓的是泄漏,仍然值得看,只是不再拦截。负载脚本沿用 `scripts/perf/budget.mjs` 的判定函数,结果以提示形式输出。
7. 运行参数(Node `--max-old-space-size=384 --max-semi-space-size=8`、SQLite 页缓存 4 MiB、`docker-compose.prod.yml` 里应用容器 `mem_limit: 512m`)是**默认的保护值,不是承诺**:部署在内存更大的机器上时可以放大。是否同步放宽这些默认值,留给业主决定(见 PR 描述)。
8. 桌面端(M10)和手机端(M11)的内存同样只测量、不设门禁。

## ADR 0018 中保留作历史的部分

ADR 0018 的背景分析、实测数据(1 万封同步的 91.7 → 161.8 MiB 问题、`--max-semi-space-size=8` 与页缓存的取舍)仍然有效,可作为排查内存问题的参考;它的规则、阈值和「实施顺序」不再生效。

## 后果

- 新功能和插件不再受固定数字限制;审查者靠报告发现明显的退化。
- 没有门禁后,泄漏类问题不会自动被拦住:报告中的 notice 需要审查者留意。若以后出现真实的泄漏,再单独加针对性的检查。
- 文档不再写「2 GB 机器」:Docker 部署文档改为「建议 2 GB 以上,以实际使用为准」。
