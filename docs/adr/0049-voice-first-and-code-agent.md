# ADR 0049 · 语音优先与编码代理(M13)

- 状态:提议(业主 2026-11-23 确认要做,本 ADR 待业主 / X 审定细节)
- 日期:2026-11-24
- 相关:ADR 0010(工具与审批)、ADR 0011(文件工具的路径校验)、ADR 0016(不可信内容)、ADR 0021(语音)、ADR 0039(预授权)、ADR 0045(手机)、ADR 0046(内置浏览器与工具可视化)、ADR 0047(工具分组)、`docs/milestones/M13-plan.md`
- 范围:本 ADR 只定设计,不含实现代码。实现按第 9 节拆成 5 个 PR。
- 语言:中文;代码标识符、API 路径和文件名保留英文。

## 0. 背景

业主 2026-11-23 确认两件事,插在 M13 的 `feat/skills-runtime` 之后、channels hub 之前:

1. **语音优先**:主界面默认用说话交互,打字退到弹窗里;以后可以一直开着麦克风连续对话。
2. **编码代理可视化**:助手能看一个本地项目的 git 历史(例如「最近第 3 次改动」)、改代码、跑测试,右侧面板实时显示它在看什么、改什么。

业主同时定了边界:**不操控 IDEA 等桌面程序**,继续遵守 ADR 0046 第 5.4 节「不合成鼠标键盘」;编码能力只用专门的工具实现,只限用户登记的项目,写文件和执行命令每次审批,默认关闭。

现状:ADR 0021 已有服务器转发的 STT / TTS、按住说话、自动发送和自动朗读;ADR 0046 已有浏览器面板、`ui.panel`、`fs.write` 的差异预览;ADR 0047 已有按需工具组。本 ADR 在这些基础上增加,不改它们的规则。

## 1. 默认输入方式

### 1.1 设置

- `Settings.voice` 增加 `inputMode: 'voice' | 'text'`,`DEFAULT_VOICE_SETTINGS.inputMode = 'voice'`。
- 只加字段,不写迁移:设置是按组合并默认值的 JSON(`packages/storage` 的 `NESTED`),老用户已存的 `voice` 里没有这个字段,读出来就是默认值 `voice`;`defaultSttProfileId`、`autoSend`、`autoSpeak` 等已存的值不变,其他设置组也不动。
- 旧服务器不返回这个字段时,客户端按 `text` 处理(旧服务器上的界面行为不变)。
- `PATCH /api/v1/settings` 的 `voice` 照旧接受部分字段。OpenAPI 只增不改。

### 1.2 没有可用的 STT 时

语音模式需要一个 purpose 含 `stt` 的模型配置档。没有时(新装还没配模型、或配置档被删)主界面自动退回文字输入框,说话按钮的位置换成一句短提示「还没有语音识别模型」和去设置的链接;`inputMode` 本身不改,配好之后自动回到语音界面。浏览器不支持录音(没有 `MediaRecorder` / 拒绝了麦克风权限)时同样退回文字,提示「无法使用麦克风」。

### 1.3 语音模式的主界面

- 主区域只有:一个大的说话按钮、字幕区、角落里的键盘按钮。会话列表、面板、知识模式等其他入口照旧在原来的位置,不受影响。
- **点按**:点一下开始录音,再点一下结束并发送。**按住**:按下超过 300 ms 视为按住说话,松开结束并发送;按住时间不到 300 ms 算点按。两种方式用同一个按钮,不需要切换。录音上限沿用 120 秒(ADR 0021 第 3 节)。
- 键盘:按钮获得焦点时空格 / 回车等同点按(无障碍);`Esc` 在录音时取消本次录音(不发送)。
- 字幕区显示两行:上面是本次转写出的用户的话(转写完成后出现,ADR 0021 的转写是整段返回,没有实时的中间结果),下面是助手回复的流式文字(最新的两三句,不是完整聊天记录)。需要看完整记录时点字幕区展开到聊天视图。字幕按文本节点渲染(ADR 0046 第 7 节)。
- 状态:按钮本身显示「正在听 / 正在想 / 正在朗读」,来源仍是 `assistant-state`(ADR 0021 第 6、7 节),`aria-live="polite"`。
- 有待审批的工具调用时,审批卡照常出现在字幕区上方;语音模式不提供「说『同意』就批准」,批准只能点卡片上的按钮(与现在相同)。

### 1.4 文字输入弹窗

- 键盘按钮,或快捷键 `Ctrl/Cmd+I`(待业主确认,见第 8 节),弹出文字输入弹窗:就是现有的输入框(附件、模型胶囊照旧),焦点自动进入。
- 发送后弹窗自动收起,回到语音界面;`Esc` 或点外面收起且不发送,草稿保留到下次打开。
- 手机上弹窗贴着屏幕键盘上方(沿用 ADR 0045 的安全区与键盘处理);手机上按住说话与点按的规则同桌面。

### 1.5 文字模式

`inputMode = 'text'` 时界面与现在完全相同(输入框里的麦克风按钮仍可按住说话)。设置页「语音」卡片里加单选「默认输入方式:语音 / 文字」,旁边一句提示「语音模式下主界面只保留说话按钮」。

## 2. 连续对话模式

### 2.1 设置

`Settings.voice` 再加两个字段(PR 2 加入):

- `continuous: boolean`,默认 `false`。
- `silenceEndSeconds: number`,整数 3–60,默认 8:连续模式下这么久没听到说话就自动结束。

### 2.2 行为

- 开启后,语音模式的说话按钮变成「开始对话 / 结束对话」。开始后麦克风一直开着,由本地的语音活动检测(VAD)断句:检测到说话开始录音,说完停顿约 800 ms 结束这一段并发送。
- **VAD 只在浏览器本地做**:用 Web Audio 的 `AnalyserNode` 算短时能量,开始时用前 300 ms 估计底噪,阈值 = 底噪之上一个固定倍数;说话要连续超过阈值约 200 ms 才算开始(过滤咳嗽、敲键盘)。不引入新依赖、不下载模型。电平永不上报服务器(ADR 0021 第 6 节)。效果不够时再评估带模型的 VAD(需过许可证白名单),写进 PR 2 的待决定事项。
- **朗读时可打断**:朗读回复时麦克风保持打开(`getUserMedia` 打开 `echoCancellation`、`noiseSuppression`);检测到用户开始说话就立即停止播放、丢弃还没播的分段,开始录这一段。打断只停朗读,不取消正在进行的运行;新的一段照常作为下一条消息发送(运行还没结束时排队,与现在连续发两条消息相同)。
- **自动结束**:`silenceEndSeconds` 秒内没检测到说话(朗读时间不算)就结束对话、关闭麦克风。另外,页面进入后台(`visibilitychange` 为 `hidden`)、断网、或麦克风被系统收回时立即结束。
- **可见性**:连续模式开着时,界面顶部始终显示「麦克风开着」的标记和结束按钮;桌面应用里窗口标题加同样的标记。
- 唤醒词不做(第 7 节)。

## 3. 编码项目

### 3.1 登记

- `Settings.code` 新增(PR 3 加入,旧服务器不返回时按关闭处理):

  ```ts
  code: {
    enabled: boolean; // 默认 false
    projects: Array<{
      id: string; // 服务器生成
      name: string; // 例如 "FatCat-AI",1–60 字符,用户可改
      path: string; // 例如 "E:\\projects\\FatCat-AI"
      commands: Array<{
        // 允许 code.run 运行的命令,最多 20 条
        name: string; // 例如 "test",[a-z0-9-]{1,32}
        argv: string[]; // 例如 ["pnpm", "test"],1–16 项,每项 ≤ 200 字符
      }>;
    }>; // 最多 20 个
  }
  ```

- **项目路径必须在已授权文件夹(`/api/v1/fs/roots`,ADR 0011)之内**,登记时用同一套 `resolveInRoots` 检查(词法检查、`realpath.native`、链接与 junction、8.3 短名),并且该路径下必须有 `.git`(目录或 worktree 的 `.git` 文件)。授权文件夹被删掉后,其中的项目在每次调用时检查失败,工具返回「项目不在已授权的文件夹里」,设置页标红。这样「哪些文件夹能动」只有一个来源。
- 登记、改名、删项目、改命令只能由用户在设置页做;没有给模型的登记工具。

### 3.2 工具

工具名与分组(ADR 0047):`git.log`、`git.show`、`git.diff`、`code.run` 都显式归入按需组 `code`(`ToolDefinition.group = 'code'`)。`Settings.code.enabled = false` 时这些工具不注册,组也不出现在系统提示的目录里。改代码复用现有的 `fs.read` / `fs.list` / `fs.search` / `fs.write`(组 `fs`),它们的规则不变。

| 工具       | 参数                                         | 风险     | 说明                                                                                             |
| ---------- | -------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------ |
| `git.log`  | `{ project, limit? (1–50, 默认 20), path? }` | read     | 当前分支沿第一父提交的最近若干次提交:序号(1 = 最近一次)、短哈希、作者名、时间、标题              |
| `git.show` | `{ project, nth? (1–200) \| sha?, path? }`   | read     | 「最近第 N 次改动」= `nth`;返回提交信息与差异                                                    |
| `git.diff` | `{ project, from?, to?, path?, staged? }`    | read     | 默认工作区相对 `HEAD` 的未提交改动;`from` / `to` 只接受 `nth` 形式的 `~N` 或 7–40 位十六进制哈希 |
| `code.run` | `{ project, command, args? }`                | external | 只运行该项目 `commands` 里登记的命令;`args` 最多 8 项,见 3.4                                     |

- `project` 是项目的 `id` 或 `name`(不区分大小写)。模型不能传路径作为项目。
- `git.*` 只读,不需要审批(与 `fs.read` 相同)。`code.run` 是 `external`,**每次审批,不能预授权**(`forceApproval`,预授权页不列出它);审批卡显示项目名、完整命令行、工作目录。`fs.write` 照旧每次审批并带差异预览。
- 返回内容(提交信息、作者名、差异、命令输出)都来自仓库,**一律按不可信内容包装**:`UntrustedContent.kind` 新增 `'code'`,会话被标为读过外部内容(ADR 0016)。提交信息或代码注释里的「忽略之前的指令」不会改变审批。
- 上限:差异沿用 ADR 0046 第 7 节的 500 行 / 64 KiB,超出时截断并标明 `truncated: true` 与被省略的文件列表;`code.run` 的输出保留最后 64 KiB(合并 stdout / stderr,按时间顺序)。

### 3.3 运行 git

- 用系统的 `git`,`execFile` 不经 shell,参数数组由工具自己拼,模型只提供经过校验的值(`nth`、哈希、项目内的相对路径)。找不到 `git` 时返回 `git_unavailable`。Windows 的 spawn 对裸名会先查当前目录(即不可信的项目文件夹),所以 Windows 上程序一律先按 PATH(只用绝对目录)与 PATHEXT 解析成绝对路径,找不到就报错,不交给 spawn;`.cmd` / `.bat` 经 `%SystemRoot%\System32\cmd.exe` 的绝对路径运行,不读 `ComSpec`。
- **仓库自己的配置可能执行命令**(`core.fsmonitor`、`diff.external`、textconv 过滤器、`core.pager`、`core.sshCommand` 等),所以每次调用都加:`-c core.fsmonitor=false -c core.hooksPath=<空目录> -c diff.external= -c core.pager=cat -c protocol.allow=never -c log.showSignature=false -c gpg.program= -c gpg.ssh.program= -c gpg.x509.program=`,子命令加 `--no-ext-diff --no-textconv --no-color`(`log` / `show` 再加 `--no-show-signature`);仓库配置的每个过滤器驱动(用 `git config -z --get-regexp` 读出,名字可含任意字符)都用 `-c` 改成空命令且不必成功,名字含换行或 `=` 无法安全覆盖时拒绝这次调用;另加 `-c diff.ignoreSubmodules=all -c submodule.recurse=false`,`diff` 加 `--ignore-submodules=all`(内嵌仓库有自己的配置,外层覆盖管不到),修订参数前加 `--end-of-options`;每次调用固定 `--work-tree=<项目真实路径>`,并在登记时与每次调用时用 `rev-parse --absolute-git-dir --git-common-dir` 确认 git 目录、共用目录、配置的 `core.worktree` 与 根对象目录与 `objects/info/alternates` 整条链(逐层取真实路径、有环停止、最多 16 层)都在授权文件夹之内。不再逐个列举 git 会跟随的指针,而是加两条规则:git 目录、共用目录和链上每个对象目录整个递归扫一遍,出现任何符号链接(Windows 的 junction 也算)就拒绝(git 自己从不在这里建链接;超过 20 万项也拒绝);alternates 条目按 git 的规则读(只按 `\n` 分行、整行原样当路径),含 `\r`、首尾空白或以 `"` 开头的条目一律拒绝。读 git 的输出和指针文件(`rev-parse` 报的 git 目录与共用目录、`core.worktree`)同样不 trim,只去掉最后一个换行,空行、`\r`、首尾空白或行数不符都拒绝。已知限制:硬链接进来的外部对象检测不到(需要攻击者在同一文件系统有写权限;本地 clone 本身会建硬链接,不能简单拒绝链接数大于 1 的文件)(`.git` 文件的 gitdir 可以指到外面);环境只保留 `PATH`、`SYSTEMROOT`(Windows)、`HOME` / `USERPROFILE`,并设 `GIT_TERMINAL_PROMPT=0`、`GIT_CONFIG_NOSYSTEM=1`、`GIT_OPTIONAL_LOCKS=0`(只读命令不写 index)。不运行 `status` 以外会刷新 index 的命令,`git.diff` 用 `diff`(不用 `status`)。
- 路径参数先过 ADR 0011 的检查,再以 `--` 之后的相对路径传给 git;`from` / `to` / `sha` 只接受上面的格式,拒绝以 `-` 开头的值。
- 超时 15 秒,输出超过上限时停止读取并结束进程。
- 备选方案(第 8 节问题 2):改用纯 JS 的 git 读取库,完全不起 git 进程。推荐先用系统 git 加上面的加固:它正确处理 packfile、worktree、换行转换,而且没有新依赖。

### 3.4 `code.run`

- 只运行登记的命令:`command` 必须等于项目某条 `commands[].name`;实际执行的是登记的 `argv`,后面追加模型给的 `args`。`args` 每项必须匹配 `^[A-Za-z0-9._/\\:=@+,-]{1,200}$`(可以是 `--filter=core`、`src/a.test.ts`、`src\a.test.ts` 这类值);不允许空格、引号、`;`、`|`、`&`、`>`、`<`、`` ` ``、`$`、`%`、`^`、`!`、换行。这样只能加测试文件名、过滤器这类值,不能拼出新的命令。
- 工作目录固定为项目路径;不经 shell(`execFile`,`shell: false`)。**Windows 的 `.cmd` / `.bat`**(例如 `pnpm.cmd`):Node 不允许不经 shell 直接运行它们,这时用 `cmd.exe /d /s /c` 运行,登记的 `argv` 与 `args` 都已经过上面的字符检查,`%` 和 `^` 不在允许范围内,因此没有可展开的变量或转义。
- 环境:继承用户环境里的 `PATH` 等,但去掉 `FATCAT_*`、`AIP_*` 与名字里含 `KEY`、`TOKEN`、`SECRET`、`PASS`、`AUTH`、`CRED`、`PAT`、`COOKIE`、`PRIVATE` 的变量,以及以 `_URL`、`_URI`、`_DSN` 结尾的连接串;不传主密钥、不传 API Key。
- 超时默认 10 分钟(登记时可设 1–60 分钟);取消运行或超时时结束整个进程树(Windows 用 `taskkill /T /F`,其他系统按进程组发 `SIGTERM` 再 `SIGKILL`)。
- 结果:`{ exitCode, durationMs, output, truncated }`。退出码非 0 不算工具出错,原样交给模型。
- 这是「执行用户自己登记的命令」,不是通用 shell:模型想运行没登记的命令时,工具返回 `unknown command: <name> (ask the user to add it in Settings → Code)`。

### 3.5 这些工具不做什么

- 不提交、不推送、不切分支、不 `reset`、不 `stash`:没有任何写 git 的工具。改代码只经 `fs.write`,结果是工作区里未提交的改动,由用户自己审阅、提交。
- 不打开 IDE、不发键盘鼠标事件;ADR 0046 第 5.4 节的检查脚本照常运行。
- 不访问网络(`protocol.allow=never` 之外,也没有 fetch / pull 一类的工具)。

## 4. 代码面板

- `ui.panel` 的 `panel` 枚举增加 `'code'`;`panelForTool` 让 `git.*`、`code.run`,以及目标路径在某个已登记项目之内的 `fs.read` / `fs.write`,打开「代码」面板。跟随、固定、8 秒自动收起、手动收起后本轮不再自动打开,规则与浏览器面板相同(ADR 0046 第 15 节)。
- 面板内容全部来自本会话的工具调用事件,**界面不自己读文件、不调 git**(ADR 0046 第 7 节「界面没有自己的文件 API」):
  - 顶部:当前项目名与路径(相对显示)。
  - 提交列表:最近一次 `git.log` 的结果;被 `git.show` 打开过的提交可以点开看差异,没打开过的显示一句「让助手打开这次改动」。
  - 差异:最近一次 `git.show` / `git.diff` 的结果,或正在审批的 `fs.write` 的差异预览;批准前不写入,面板上没有自己的批准按钮(审批仍在审批卡上)。
  - 测试输出:`code.run` 的结果;运行中显示「正在运行 <命令>」与已用时间,结束后显示退出码和输出末尾。
- 渲染沿用 ADR 0046 第 7 节:只用文本节点,控制字符与双向字符替换成可见标记,500 行 / 64 KiB 上限,列表虚拟化。
- 手机上「代码」面板作为单栏里的一个标签页(ADR 0045),内容相同。

## 5. 语音指令端到端

两条固定用例(PR 5),都用假模型回放脚本和 Chromium 假麦克风:

1. 说「打开浏览器搜 xxx」:转写 → 模型 `tools.enable browser` → `browser.open` → 浏览器面板打开并显示页面(Web 端用现有的假 webview 桩)。
2. 说「打开 FatCat-AI 项目,看最近第 3 次改动,修一下 bug」:转写 → `tools.enable code` → `git.show { project: 'FatCat-AI', nth: 3 }` → `fs.read` → `fs.write`(审批卡出现,点同意) → `code.run test`(审批卡出现,点同意) → 代码面板依次显示提交差异、文件差异、测试输出。测试仓库是测试里临时 `git init` 的小仓库,登记为项目;`test` 命令是 `node -e` 打印一行。

假麦克风用 Chromium 的 `--use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<wav>`,沿用 `apps/web/e2e/voice.e2e.ts` 的假 STT 端点(按请求顺序返回预设文字)。

- 唤醒词(「胖猫胖猫」一类的免按键唤醒):需要常驻的本地关键词模型和更严格的隐私设计,另写 ADR。

## 8. 需业主决定的事项(附推荐)

1. **老用户是否也默认切到语音模式?** 推荐:是(业主要求默认语音),没有 STT 配置档时自动退回文字(第 1.2 节),所以没配语音的老用户看不到变化。
2. **git 的实现**:系统 `git` 加固(推荐,第 3.3 节)还是纯 JS 读取库。
3. **代码面板能不能自己取提交差异?** 推荐:不能,只显示工具结果(第 4 节),保持「界面没有自己的文件 API」;以后确有需要再加只读接口并补 ADR。
4. **打开文字弹窗的快捷键**:推荐 `Ctrl/Cmd+I`(`Ctrl+K` 已是命令面板,`/` 在手机上不好按)。
5. **`code.run` 默认超时**:推荐 10 分钟,登记命令时可改(1–60 分钟)。
6. **连续模式的 VAD**:先用无依赖的能量阈值(推荐);误触发多时再评估带模型的 VAD。

### 10.3 只用语音输入(PR `feat/voice-only-input`)

- **默认开着连续语音**:`DEFAULT_VOICE_SETTINGS.continuous` 改为 `true`。只改默认值、不写迁移:从没改过这个开关的老用户读出来就是开着,改过(存了 `false`)的保留;旧服务器不返回这个字段时客户端仍按 `false` 处理。
- **自动开始聆听**:语音模式的主界面(第 10.1 节)打开时,满足下面全部条件就直接开始连续对话,不用点球:页面在前台;`navigator.permissions.query({ name: 'microphone' })` 已经是 `granted`(没授权过时不自动弹授权框,第一次要由用户点球);共享的 `AudioContext` 在 300 ms 内能进入 `running`(浏览器的自动播放策略不允许时等用户点球,免得开着麦克风却听不到声音)。查询失败、浏览器不支持权限查询都按不满足处理。
- **什么时候不再自动打开**:用户点球或按 `Esc` 暂停、静音超时、断网、麦克风被收回、出错之后,直到刷新页面都不再自动打开,等用户点球。只有切到后台(`hidden`)和离开聊天页(`left`)造成的结束,回到前台 / 回到主界面时自动恢复。
- **点球 = 暂停 / 继续聆听**:连续对话里球的标签是「暂停聆听」「继续聆听」;回复进行中点球仍只停止这次回复(第 10.1 节)。静音、断网等的提示改成「已暂停聆听」。完整对话里「麦克风开着」条上的按钮也改叫「暂停聆听」。
- **手机手势**(只看触摸事件,鼠标不受影响):在球上按住 500 ms 且移动不超过 10 px 打开文字弹窗,聆听不中断,松手后那次点击不算点球;只说话模式(连续对话关着)里按住球是按住说话,不算长按。在主界面任意位置往上滑超过 60 px(竖直位移大于水平位移)打开完整对话,文字弹窗开着时不处理。球上关掉系统的长按菜单(`-webkit-touch-callout: none`)。
- **没有语音识别时**:仍按第 1.2 节退回文字输入框,第一行是一句短提示加「去设置」链接,没有按钮。没有改成「极简主界面 + 状态行提示」:没有语音识别时主界面上就没有能说话的东西,手机上也只能靠长按打字;而且现有的大部分端到端用例都在没有语音识别的默认设置下直接用输入框。这一点列为待业主决定的问题,业主要改再单独做。

### 10.4 球的状态色(PR `feat/sphere-states`)

- **状态**:主视觉接口 `Hero.setState` 在助手状态之外多一个 `heard`(检测到语音)。它只在本机的连续对话里出现(VAD 确认开始说话),不进 `AssistantState`、不上报服务器;运动按聆听处理,只换颜色。界面的 `VoiceIndicator` 多一个 `heard` 属性,并在 `data-hero` 上写出主视觉当前的状态(端到端测试用)。
- **颜色**:每套主题四种状态色,写在 `packages/ui/src/tokens.css`:科技 `--hero-state-*`、自然 `--nature-state-*`、猫 `--cat-state-*`(和各自的主视觉配色一样定义在 `:root`,主题选择器的预览也能用)。科技为基准:聆听淡蓝白、检测到语音亮绿、思考紫、说话深亮蓝;自然同样的色相,调亮以配合暗色森林;猫在奶油底上,换成更深、更饱和的同色相。待机不染色。
- **染在哪里**:科技染一部分星点(聆听约 55%、思考 65%、检测到语音与说话 75%,按星点自己的随机序挑,不闪烁)和星云雾;自然染树冠光点和萤火,枝干保持金色;猫染轮廓线和光点的光晕,亮芯与胡须不变。自然和猫的线条是混色,互补色按比例混合会发灰,所以按最高比例归一(聆听时也基本是状态色)。
- **过渡**:颜色与染色比例每帧按指数缓动靠近目标(时间常数 140 ms,约半秒到位);从待机进入某个状态时颜色直接取目标色,只有比例慢慢升,不会闪过别的颜色。科技的转速和摆动同样缓动(时间常数 260 ms),换状态时不会突然反转。
- **运动**:科技聆听慢转;思考反向自转并且球轴前后摆动(换一种转法);说话时星点只向外脉动,幅度随朗读音量(`level` 来自播放的电平)。自然与猫沿用原来各状态的动效(思考时光沿树干爬升、说话时树随音量摇动、光顺着猫的轮廓流动)。
- **减少动态**:`prefers-reduced-motion` 时每次状态变化只画一帧,颜色直接换到目标色,不转、不摆、不脉动。
- 纯函数在 `packages/ui/src/heroes/state-tint.ts`(`tintTarget`、`stepTint`、`parseColor`、`readStateColors`),单测在 `state-tint.test.ts`,其中检查三套主题在 tokens.css 里都有四种状态色。

### 10.5 工作态(PR `feat/workbench-split`)

- **触发**:极简主界面(第 10.1 节)上工具面板打开时(工具调用、`ui.panel` 或命令面板),外壳加 `data-working`;手机(`narrow`)见第 10.6 节。面板的开关、跟随、8 秒自动收起等规则不变(ADR 0046 第 15 节)。
- **布局**:舞台(球、三行文字、审批卡)宽度从 100% 缩到 34%,球缩小(`min(24vh, 24vw)`),宽度用 0.35 秒过渡;面板从右侧浮出,左边贴在舞台右侧加一格间距,占剩下约 2/3 宽,圆角 20 px,顶部留出 64 px 给右上角的工具名。关闭面板后舞台回到全宽,球回到中央并放大(同一个过渡)。
- **工具胶囊**:原来的「正在运行的工具」卡片在极简主界面上换成竖排的小胶囊(`wb-pills`),和面板顶端对齐、贴着舞台右边(球的右侧),不压到字幕和审批卡;每个胶囊是状态图标加工具名,完整摘要在 `title` 里;完成的 1.6 秒后淡出,失败的保留红色。条数上限沿用 `visibleToolRows`。
- **右上角工具名**:有正在执行或等审批的工具时,右上角显示一个小胶囊(转圈 + 工具名,`role="status"`),没有就收起;面板没打开时它在「麦克风开着」标记下面。
- **减少动态**:不做宽度与淡入淡出的过渡,完成的胶囊到时直接隐去。
- 文字模式和非极简的工作台布局不变。

### 10.6 手机(PR `feat/main-screen-mobile`)

- **待机**:手机(`narrow`)上的极简主界面同样没有按钮,球居中,字幕和审批卡在底部安全区(`env(safe-area-inset-bottom)`)之上;左上角小圆 logo 仍是菜单入口(第 10.1 节)。

### 10.7 说话时的动效(PR `feat/speaking-effects`,业主 2026-11-25)

朗读电平仍只在本机(`Hero.setLevel`,不上报)。三套主题在 `speaking` 时跟着这个电平动;主界面不另加按钮或说明。

- **科技**:保留原来的向外脉动。另加一层呼吸灯亮度:平滑音量(时间常数 260 ms)乘到星点、星云和星座连线上,一步不会跳满,所以不是硬闪。说话结束(状态离开 `speaking`,或电平变为空)后同一条曲线缓回原来的亮度。球的缩放仍是原来那一点脉动,不另加呼吸缩放。
- **自然**:树枝仍按原来的幅度随音量轻摆。另加落叶:音量越高,同一时间在落的越多,但是一片一片放(单步最多一片,卡顿恢复也不倒下来)。叶子从树冠附近往下,靠近地面淡出,空位回收,不在地上堆。说话停止后不再放新的;约 3.2 秒后还在落的也停。知识模式不落叶。
- **猫**:嘴张开的程度跟着音量(合上时仍是原来的线稿);耳朵和尾巴只再动一点,幅度也跟着音量,比思考时的甩尾小。头旁边偶尔出现一个「喵~」(同时最多一个,几秒一个,音量太低不出现),可可棕字写在白底上。可选的一声在「设置 → 模型 → 语音」,`VoiceSettings.meow`,默认 `false`;旧存档和旧服务器没有这个字段时按关闭。开了也只在猫咪主题、朗读进行中,用很短的合成下滑音(峰值增益 0.04),并且开始朗读后先隔几秒,避免盖住开头。
- **减少动态**:只保留状态色。不落叶、不呼吸缩放、嘴不合上再张开、耳朵尾巴不另动、不冒气泡、亮度也不跟着音量走。
- **手机**:星点仍走原来的画质预算(屏幕短边 < 600 从 60% 起步)。落叶另有硬上限:手机或很小的画布最多 8 片,桌面 22 片。
- **契约**:只给 `VoiceSettings` 加可选布尔 `meow`,不写迁移,OpenAPI 只增不改。
