---
title: 工具组
description: 助手怎样按需开启文件、邮件、浏览器等工具,以及每次回答的步数和 token 上限。
---

工具越来越多以后,每一步都把全部工具说明发给模型会占上下文,也更容易调错工具。所以普通对话里,助手一开始只拿到一小组常用工具,其余工具按组放着,需要时先开启(设计见 ADR 0047)。

## 始终可用的工具

记忆(`memory.*`)、计算(`calc`)、时间(`time`)、条目和知识库(`items.*`、`kb.search`)、界面面板(`ui.panel`)、委派(`delegate`,只有设置了委派的代理才有),以及开启工具组的 `tools.enable`。

## 按需开启的工具组

| 组                 | 内容                                              |
| ------------------ | ------------------------------------------------- |
| `fs`               | 授权目录里的文件                                  |
| `mail`             | 邮件                                              |
| `web`              | 读取网页(`web.fetch`)                             |
| `browser`          | 浏览器工具(设置里打开后才有)                      |
| `channel`          | 推送到聊天渠道                                    |
| `system`           | 用默认程序打开文件和链接(设置里打开后才有)        |
| `code`             | 编码项目的 git 记录与登记的命令(设置里打开后才有) |
| `mcp.<服务器名>`   | 某个 MCP 服务器的全部工具                         |
| `plugin.<插件 id>` | 某个插件的全部工具                                |

系统提示末尾有一行这些组的目录。助手需要读文件时,会先调用 `tools.enable`(参数 `{ "group": "fs" }`),再调用 `fs.read`。

- 开启只在这一次回答里有效:下一条消息又从常用工具开始,也不会写进数据库。
- **开启一个组不改变任何审批。**写文件、发邮件、访问新网站该弹审批的照样弹,预授权和「会话读过外部内容后条件预授权失效」的规则也不变。
- 没开启就直接调用组里的工具,会得到 `unknown tool: fs.read (enable group fs with tools.enable first)`,这次调用按未知工具记入审计,不执行。

## 编码项目(`code` 组)

在「设置 → 工具插件 → 代码」打开开关并登记项目后才有这一组。项目必须在「文件」里已授权的文件夹之内,并且是 git 仓库;授权文件夹被删掉后,其中的项目也不能再用。

- `git.log`、`git.show`、`git.diff` 只读:看最近的提交、「最近第 3 次改动」(`nth: 3`)和工作区里还没提交的改动,不需要审批。git 以加固方式运行,仓库自己的配置(钩子、过滤器、外部 diff 等)不会执行任何命令。
- `code.run` 只运行你给这个项目登记的命令(例如 `test` → `pnpm test`),可以追加最多 8 个简单参数(测试文件名、过滤器),**每次都要你批准,不能预授权**。不经 shell,环境里去掉了名字像密钥的变量;取消或超时时结束整个进程树。 助手追加的参数会在审批卡上单独高亮;只登记固定用途的命令(例如 `pnpm test`),不要登记 `git`、`npx` 这类通用命令,否则追加的 `-c`、`--config=` 等选项能改变它的行为。
- `.git` 里有符号链接或 junction 的仓库(例如 `repo` 工具管理的仓库),以及仓库数据(git 目录、alternates、`core.worktree`)指到授权文件夹之外的仓库,都不能登记。需要时在授权文件夹里普通地 `git clone` 一份(不加 `--shared`)。
- 改代码仍用文件工具 `fs.write`,每次审批。没有提交、推送、切分支之类写 git 的工具。
- 提交信息、差异和命令输出都按外部内容处理,读过之后条件预授权失效。
- 工作台右侧的「代码」面板显示当前项目、最近的提交、打开过的提交与未提交改动的差异、正在审批的修改,以及测试输出(运行中显示已用时间,结束后显示退出码和输出末尾)。内容全部来自助手这次对话里的工具调用,面板自己不读文件、不调 git,也没有批准按钮。手机上它是底部的「代码」标签。

## 定时任务与代理

任务或代理设置了工具集(`toolSet`)时,工具集里点名的工具直接可用,不需要先开启;工具集之外的组也开启不了。没有工具集的定时任务和普通对话一样按组开启;输出到聊天渠道的任务一开始就能用 `channel.push`。

## 步数和 token 上限

- 普通对话和定时任务每次回答最多和工具来回 10 步(以前是 5 步);代理用自己的「最多步数」设置。
- 普通对话和定时任务每次回答还有 60,000 token 的预算,所有步骤的用量累加。用完后不再开始下一步,回答末尾会说明已用完预算,你可以让助手继续。代理沿用自己的 token 和时间预算。
