## 默认值

- **只监听 `127.0.0.1`。** 要从别的机器访问,必须放在反向代理和 HTTPS 后面,见 [Docker 部署指南](/FatCat-AI/guides/docker/)。
- **危险操作默认需要批准。** 写文件、发邮件、保存记忆等工具调用会先在界面(或微信里)显示摘要,你批准后才执行;长期放行必须你明确选择「总是」。
- **外部内容一律不可信。** 网页、邮件、文件和子代理的输出都被当作数据而不是指令,不会因为里面写了「忽略之前的要求」就改变行为。
- **对外发送一律需要批准。** 发邮件、向渠道发消息之前都要你确认。
- **没有遥测。** 不含统计或崩溃上报代码;程序只连接你配置的模型、邮箱、渠道和插件,外加一个可关闭的 GitHub Releases 更新检查。
- **日志只写本地**,是 JSON 行文件,永不外传;API 密钥不进日志、不回显。

## 公开部署前要做的事

1. 创建主人账户,用完设置码后清空 `FATCAT_AI_SETUP_CODE`。
2. 开启**两步验证(TOTP)**:「设置 → 安全」,妥善保管 10 个恢复码。
3. **加密密钥文件**:「设置 → 密钥 → 加密密钥文件」;主密钥要另外备份,丢了就打不开加密的密钥。
4. 检查「设置 → 出站目标」:列表里应该只有你在用的模型、邮箱等地址。
5. 确认应用容器没有对外发布端口,只有 Caddy 对外。

## 权限边界

- **文件工具**只能访问你授权过的文件夹;服务器会解析链接和短名称并保存真实路径,整个磁盘不能授权。
- **多代理**:子代理只能使用它自己和委派者工具集的交集,不能越过白名单。
- **插件**在沙箱里运行,只拿到它声明并获你批准的权限。

## 报告漏洞

请**不要**在公开 Issue 里报告安全漏洞。发邮件到 x19169738916@163.com,标题以「[FatCat-AI Security]」开头,附上受影响版本、复现步骤和影响范围;或使用 GitHub 的[私密漏洞报告](https://github.com/CodingLossy/FatCat-AI/security/advisories/new)。我们会在 5 个工作日内确认收到。只有最新的次版本接收安全更新。
